# Анимированный фон лендинга (background canvas)

> Декоративный PIXI-фон главной страницы. Код: [BackgroundCanvas](../../src/pages/main/BackgroundCanvas/index.tsx) (React-обёртка), [bg.ts](../../src/stores/bg.ts) (`BgStore` — вся логика), [bg-blobs.ts](../../src/constants/bg-blobs.ts) (конфиг блобов), [create-blob-texture.ts](../../src/utils/create-blob-texture.ts) (текстура).

## Назначение

Мягко анимированный градиентный фон под контентом лендинга ([MainPage](../../src/pages/main/index.tsx)): несколько размытых цветных «пятен» (блобов), медленно дрейфующих и пульсирующих.

## Зачем (какую задачу решает)

- **Визуальная айдентика** первого экрана — «живой», но ненавязчивый фон, не отвлекающий от заголовка и кнопки.
- **Полигон для React ↔ PIXI-моста** — на нём отработан канон монтирования канваса: store владеет PIXI-приложением, React лишь даёт контейнер и управляет жизненным циклом через `useEffect`.
- **Дёшево по ресурсам** — намеренно облегчён (`antialias: false`, `resolution: 1`, `powerPreference: 'low-power'`), чтобы декоративный фон не тратил бюджет кадра.

## Бизнес-логика и принципы работы

- **Блобы как спрайты.** Каждый блоб — `Sprite` с одной общей радиально-градиентной текстурой (непрозрачный центр → прозрачный край), нарисованной один раз на offscreen-canvas в `createBlobTexture`. Цвет и прозрачность блоба задаются через `tint`/`alpha` — так одна текстура переиспользуется для всех пятен.
- **Размытие — на контейнере, не на спрайтах.** Все блобы лежат в одном `Container` с единым `BlurFilter`. Один фильтр на группу дешевле, чем блюр на каждый спрайт.
- **Движение — детерминированное, без физики.** В тикере накапливается `elapsed` (сек), а позиция и размер каждого блоба считаются как функции синуса от времени (`layout()`): дрейф по X/Y плюс медленная пульсация масштаба. У каждого блоба свои частоты и фазы (`BG_BLOBS`), поэтому пятна не ходят синхронно. Всё выражено в долях экрана → корректно при любом ресайзе.
- **Ресайз** — только через опцию PIXI `resizeTo: container`; `layout()` каждый кадр берёт актуальные `app.screen.width/height`. Ручных listener'ов нет.
- **Доступность.** Тикер (анимация) подключается только если не выставлен `prefers-reduced-motion`. При reduced-motion фон рендерится статично — один прогон `layout()` без тикера.
- **Жизненный цикл — внутри стора.** `BgStore.mount(container)` создаёт и инициализирует `Application`, `unmount()` снимает тикер и уничтожает app/текстуру/спрайты. React-компонент вызывает их из `useEffect` с cleanup.
- **Защита от гонки StrictMode.** В dev React монтирует эффекты дважды. Поле `pending` хранит «актуальный» app: после `await app.init()` проверяем `this.pending !== app`, и если нас уже сменил новый монтаж — уничтожаем лишний app и выходим. Иначе получили бы два канваса и утечку.
- **Реактивность MobX — минимальная.** Наблюдаемое только `isReady`; тяжёлые PIXI-поля (`app`, `texture`, `sprites`, `elapsed`, `pending`) исключены из наблюдения. Мутация `isReady` в async-коде — через `runInAction`. Сейчас `isReady` выставляется, но в UI ещё не читается.

## Эвенты / контракты

Нет. Модуль самодостаточен и декоративен: не ходит в сеть, не подписан на эвенты, не зависит от игровых сторов. Публичный API стора: `mount(container)` / `unmount()`.

## Связи и зависимости

- [BackgroundCanvas](../../src/pages/main/BackgroundCanvas/index.tsx) — тонкая React-обёртка: даёт `div`-контейнер и дёргает `bgStore.mount/unmount`.
- [bgStore](../../src/stores/bg.ts) — вся логика и владение PIXI-приложением.
- [BG_BLOBS](../../src/constants/bg-blobs.ts) — конфиг блобов (цвет, размер, амплитуды/частоты/фазы дрейфа и пульсации).
- [createBlobTexture](../../src/utils/create-blob-texture.ts) — генерирует общую градиентную текстуру.
