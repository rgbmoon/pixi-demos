Рил-машина

Барабаны слот-машины: headless-модель, PIXI-адаптер и подключение игры.

Для чтения нужны TypeScript и базовый PIXI: Container (узел дерева отображения), Ticker (цикл кадров поверх requestAnimationFrame), маска контейнера. Окружение проекта — DI, MobX, конечный автомат фаз — кратко разобрано в разделе «Встраивание в слот», подробно в CLAUDE.md.

ядро core/reels адаптер engine/reels игра games/slot рантайм-импорт, вызов import type, implements, возврат событие эмиттера Stop и промотка

Три идеи

  1. Результат раунда присылает сервер. Клиент ничего не вычисляет: машина получает кадр через setData и анимирует барабаны до него.
  2. Лента устроена как виртуальный список. На барабан приходится rows + buffer слотов (в слоте 3 + 1) и столько же view-объектов. Слот, перешедший нижнюю границу, появляется в буфере над маской и получает новое значение, пока его не видно.
  3. Посадка — расписание, вычисленное один раз. Когда приходит ответ, стратегия считает весь путь ленты до остановки. Остаток пути известен на любом кадре, поэтому каждый обёрнутый слот сразу получает значение того ряда, где остановится.

Модель

Данные раунда

Форму данных выбирает игра, ядро читает их через accessorFn. Слот хранит кадр как [барабан][ряд]:

const frame: SlotReelsData = [['A', 'K', 'W'], ['S', 'A', 'A'], ['W', 'M', 'K'], ['E', 'S', 'N'], ['O', 'P', 'A']]
// accessorFn: (data, { reel, row }) => data[reel]?.[row]  →  ячейка { reel: 1, row: 0 } — 'S'

Hold & Win хранит поле 5×3 так же, но машина бонуса состоит из 15 барабанов высотой 1, и её accessorFn переводит номер барабана в адрес ячейки поля (toHoldWinCell).

Лента

Барабан 5×3 — пять независимых лент. Слоты барабана лежат на замкнутой ленте длиной stripHeight = (rows + buffer) * cellHeight. ReelStrip хранит путь ленты offset и базу каждого слота — позицию на неподвижной ленте:

позиция слота i = wrapOffset(base[i] + offset)     диапазон [-buffer * cellHeight, rows * cellHeight)
база слота i    = cellHeight * (i - buffer), пока каскад не переставил слоты

Слот, у которого сменился номер круга (getLap), считается обёрнутым и получает новое значение. Номер круга меняется при переходе границы в обе стороны, поэтому направление движения ленты не важно.

На прокрутке cell.getValue() уже возвращает результат раунда, а cell.getSlot() — слот, который стоит в ячейке на экране. После посадки значения совпадают.

Единицы

Ядро считает в единицах длины из конфига: cellHeight модели задаёт единицу. Адаптер переводит их в пиксели множителем ReelsViewConfig.cellHeight / ReelsModel.cellHeight. Слот задаёт обе высоты в пикселях зоны символов, множитель равен 1; модель с cellHeight: 1 считает в ячейках.

Время считается в кадрах: deltaFrames = 1 при 60 fps, как Ticker.deltaTime у PIXI. Скорости заданы в единицах за кадр, ускорения — в единицах за кадр². Поэтому движение не зависит от частоты экрана: на 120 Hz шаг вдвое короче, кадров вдвое больше.

Контракты между частями

Игра → ядро: ReelsConfig

Типы — в core/reels/types.ts, конфиг слота — games/slot/reels.ts.

  • reels — описания барабанов ReelDef; каждое поле конфига перекрывается на барабане: ряды, буфер, стратегии, аксессор.
  • accessorFn(data, { reel, row }) — значение ячейки из данных раунда.
  • getFillerValue(reel) — значение слота вне результата: на прокрутке и в буфере.
  • spinStrategy, landingStrategy, необязательный fallStrategy — стратегии по умолчанию.

Ядро → адаптер: ReelsModel

Адаптер обращается к модели только через этот контракт; ReelsMachine и Reel его реализуют.

Игра → адаптер: CellView и ReelsViewConfig

ReelsViewConfig — cellWidth, cellHeight в пикселях, фабрика createCellView и необязательная раскладка getReelPosition(index) (центр верхней ячейки ленты, по умолчанию (cellWidth * index, 0)).

Жизненный цикл барабана

Кадр

На машину приходится один тикер-колбэк. Сначала модель продвигается на шаг, затем адаптер переносит в view только барабаны, у которых выросла ревизия. deltaTime тикера — время кадра в долях кадра при 60 fps.

Фазы

Reel хранит одно текущее движение ReelMotion из motions/. Фаза барабана совпадает с фазой движения, без движения барабан в idle. advance передаёт шаг движению и снимает его, когда isDone() возвращает true; посадка и падение при этом резолвят промис вызова.

Машина

ReelsMachine вызывает методы барабанов и вычисляет параметры, которые зависят от соседних барабанов: место в лесенке и число пауз anticipation. Опции — в types.ts.

  • spin({ held }) — удержанные барабаны остаются в idle со слотами прошлого раунда. Данные раунда обязаны повторять их значения.
  • land({ anticipation, slamSignal, signal, onReelLanded, onReelAnticipated }) — сажает крутящиеся барабаны. Место в лесенке order — номер среди садящихся, удержанные не считаются. Барабан получает паузу за каждый барабан из anticipation с индексом не больше своего, поэтому барабан правее ждущего соседа тоже сдвигается. Собственная пауза (isAnticipating) есть только у барабанов из списка; начало паузы объявляет onReelAnticipated синхронно из advance.
  • cascade({ removed, slamSignal, signal, onReelLanded }) — падение в барабанах с ячейками из removed. Нужна fallStrategy, без неё барабан бросает ошибку конфигурации.
  • slamSignal — сигнал промотки: сработавший до вызова приводит к slam() сразу после старта движений, сработавший по ходу — в момент срабатывания. О промотанной паузе anticipation колбэк не сообщает: slam переносит время вне advance.

Как слот получает финальное значение

На любом кадре посадки точка остановки слота равна его текущей позиции плюс непройденный остаток пути. Reel.fillLanding при каждой обёртке вычисляет ряд этой точки. Если точка ниже видимой зоны, слоту предстоит ещё круг, и он получает наполнение; иначе он получает значение ряда из данных и позу покоя. Поэтому на последнем обороте слот уже показывает финальный символ.

Каскад

  1. Уцелевшие слоты сохраняют порядок и опускаются на число убранных рядов под ними; слот, чей ряд не изменился, стоит на месте.
  2. Убранные слоты получают значения новых верхних рядов 0..k-1 из данных, выстраиваются столбиком над зоной и падают на k ячеек. Буферный слот не двигается.
  3. FallMotion перемещает каждый слот по своему пути из FallPlan, в обход свёртки ленты. Значения на падении не меняются.
  4. На последнем кадре слоты становятся точно на ряды, текущие позиции становятся базами (rebase), путь обнуляется. Следующий спин считает позиции от новых баз.

Данные раунда обязаны повторять значения уцелевших слотов.

Стратегии

Стратегия — объект с одним методом, который машина получает из конфига. Готовые лежат в strategies/.

ИнтерфейсМетодРезультат
SpinStrategystep(deltaFrames, ReelContext)путь ленты за кадр
LandingStrategyplan(LandingContext) один раз на посадкуLandingPlan: distance, totalFrames, settleFrames, anticipationFrames?, positionAt(frames)
FallStrategyplan(FallContext) один раз на падениеFallPlan: totalFrames, settleFrames, positionAt(drop, frames)

settleFrames — начало финального участка: до этого кадра slam проматывает движение. Стратегия без финального участка отдаёт totalFrames, и по slam барабан встаёт сразу. Шаг прокрутки может быть отрицательным: номер круга меняется в обе стороны, правок ядра это не требует.

PlannedLandingStrategy

путь = оборот ленты + недокрученный минимум вращения + order * staggerCells
       + anticipationPauses * anticipationCells + тормозной путь + хвост отскока + добор до границы ячейки

  скорость
     speed ├──────────────┐
           │  равномерно   \  линейное торможение
  handover │                \────┐
           │                     │  отскок easeOutBack
         0 └─────────────────────┴──── кадры
  • Оборот ленты в пути гарантирует, что каждый слот обернётся и получит значение раунда.
  • Добор до границы ячейки делает путь кратным ячейке, и лента останавливается ровно на границе.
  • Минимум вращения minSpinFrames считается вместе с кадрами до посадки: при раннем ответе сервера равномерный участок удлиняется. Длительность спина не зависит от скорости сети.
  • Паузы anticipation идут на равномерном участке, поэтому slam проматывает их вместе с ним.
  • Длительность отскока подобрана по производной кривой в нуле: скорость на входе в отскок равна handoverSpeed, скачка скорости нет. Точка промотки — начало отскока.

Кадры ниже посчитаны PlannedLandingStrategy с настройками слота из reels.ts: ответ пришёл на 40-м кадре прокрутки, сервер отправил в anticipation барабаны 3 и 4.

GravityFallStrategy

старт слота = order * staggerFrames + (нижний ряд падения - ряд слота) * rowStaggerFrames
путь слота  = gravity * t² / 2 до касания ряда, затем отскок на bounceCells за bounceFrames

Нижний слот барабана стартует первым, слот выше падает не меньше соседа снизу, поэтому слоты не перекрываются. Точка промотки — кадр касания последнего слота.

Наборы стратегий игры

Скорость прокрутки обязана совпадать со скоростью равномерного участка посадки, иначе на входе в посадку скорость ленты скачет. Поэтому слот собирает наборы фабрикой createStrategies в reels.ts: одна скорость на обе стратегии, ускорения растут квадратом множителя турбо. Турбо-режим меняет набор через machine.setStrategies.

Встраивание в слот

Окружение проекта

  • Конечный автомат фаз (core/fsm). Фаза — класс с методом enter(signal), который выполняет свою часть раунда и возвращает имя следующей фазы. Фазы слота лежат в games/slot/phases/. signal отменяет фазу при уходе со страницы.
  • Стор (stores/slot.ts) — класс MobX. В него пишут только фазы, остальные читают. Ответ сервера лежит там как есть, геттеры (spinSymbols, nextCascade, heldReels) извлекают из него данные текущего шага.
  • Контроллер — PIXI-контейнер, наследник LiveContainer. Подписки на стор оформляются через this.watch(выражение, эффект) и снимаются при destroy. Фазы вызывают методы контроллеров и ждут их промисы.
  • Эмиттер — типизированные события (reel:landed, ui:stopRequested). Контроллеры сообщают через него о моментах раунда, звук на них подписан.
  • DI (inversify) создаёт фазы, стор и контроллеры верхнего уровня. Вложенные контроллеры создаёт их владелец через new.

Спин по шагам

Фаза spinning запускает прокрутку и запрос одновременно: лента крутится, пока идёт запрос, и после ответа останавливается на присланном кадре.

Stop. Кнопка эмитит ui:stopRequested, фаза превращает событие в stopSignal через emitter.signalOn, контроллер передаёт сигнал в land / cascade машины как slamSignal.

Hold & Win — вторая машина на тех же классах. Игра передаёт второй конфиг (15 барабанов высотой 1), раскладку сеткой getReelPosition и свою реализацию CellView — Coin. Ленты с одинаковым y делят маску-полосу, поэтому поле из 15 лент рисует три маски. Доски меняются местами вызовами show/hide контроллеров из фаз бонуса.

Как читать код

Маршрут одного спина от фазы до пикселя:

  1. phases/spinning.ts — reels.spin(), запрос, applySpin, reels.land(...).
  2. controllers/reels/reels-machine.ts — land: setData и machine.land({ anticipation, slamSignal, колбэки }).
  3. core/reels/reels-machine.ts — land: место в лесенке и паузы для каждого барабана, awaitWithSlam.
  4. core/reels/reel.ts — land: план стратегии и LandingMotion; fillLanding — значение обёрнутого слота.
  5. strategies/planned-landing.ts — расписание.
  6. motions/landing-motion.ts — advance: позиция по расписанию → strip.moveTo.
  7. core/reels/reel-strip.ts — moveTo, свёртка, snap.
  8. engine/reels/reels-view.ts — step → advance → sync; reel-view.ts — запись в view.
  9. ui/reels/reel-symbol.ts — реализация CellView.

Механику раунда выбирает сервер, клиент показывает её по данным ответа. Адаптер меняется только ради нового способа раскладки лент или отрисовки; расчёт позиций к нему не относится.

Инварианты

  • Один вызов advance на кадр. advance модели вызывает только тикер-колбэк ReelsView. Второй адаптер на ту же модель продвинет её дважды за кадр.
  • Адаптер пропускает барабаны без правок. getRevision() растёт на каждой правке ленты. Пока барабан стоит, контроллер может перенести его view в другой контейнер (оверлей выигрыша поднимает символы над затемнением), и адаптер их позиции не перезаписывает.
  • Граница диапазона ленты. Точка покоя слота может попасть ровно на границу диапазона, и сторону результата % определяет ошибка округления: слот оказывается под зоной, соответствие «слот → ряд» сдвигается на единицу. wrapOffset и getLap применяют одинаковый допуск WRAP_EPSILON. Регрессию закрывает тест свёртки ленты.
  • snap() не меняет позы. Позу покоя каждый слот получил на последнем обороте; повторная смена сбросила бы фазу idle-анимации.
  • Порядок getStrip() стабилен, порядок getVisibleSlotIndices() пересчитывается по позициям. View слота адаптер хранит по индексу из getStrip().
  • После падения базы переписываются. Без rebase первый сдвиг ленты вернул бы слоты на старые места.
  • View взорванных ячеек берутся до machine.cascade. getCellView ищет view по позициям, а каскад переставляет слоты синхронно.
  • Одна маска на полосу раскладки. Маска PIXI 8 — stencil: прерывает батч и рисуется дважды. Скрытая доска (visible = false) масок не рисует.

API без использования

Row / getRows(), getGrid(), CellContext / Cell.getContext(), ReelMeta / ReelDef.meta и ReelsConfig.data не вызываются ни игрой, ни адаптером. Они оставлены как API библиотеки для механик, которым нужен обход по рядам, контекст ячейки или свои данные барабана.

Вынос в пакеты

  • src/core/reels/ переносится вместе с src/core/easing (её использует PlannedLandingStrategy) либо получает кривую отскока опцией стратегии.
  • src/engine/reels/ зависит от pixi.js и типов ядра; тикер — любой PIXI Ticker.
  • Игра остаётся в своём пакете: конфиг, реализация CellView, контроллеры и раскладка.
Код: src/core/reels, src/engine/reels, src/games/slot. Соседний документ — «Тестовая стратегия».
