Рил-машина

Headless-модель барабанов слот-машины и PIXI-адаптер к ней.

Начало

Введение

Рил-машина — модуль барабанов для слот-игр: вращение барабанов и их остановка на символах результата раунда. Результат раунда вычисляет сервер или другой код игры.

Задачи, которые рил-машина решает из коробки:

  • Спин и посадка — барабаны вращаются и останавливаются на символах результата раунда.
  • Stagger — барабаны останавливаются по очереди, слева направо.
  • Минимальная длительность спина — спин длится не меньше заданного времени, даже если результат пришёл сразу.
  • Anticipation — барабан, который может дать бонус, вращается дольше остальных.
  • Slam stop — по нажатию Stop барабаны сразу переходят к финальному отскоку.
  • Респин — повторный спин, в котором часть барабанов удержана на месте.
  • Каскад — уцелевшие символы падают на место убранных, сверху падают новые.
  • Hold & Win — поле из ячеек, каждая из которых вращается отдельно.
  • Турбо — между спинами меняются скорость и профиль движения барабанов.
  • Символ по адресу ячейки — отображаемый символ находится по адресу (барабан, ряд): для подсветки выигрыша и анимаций символов.

Другие игровые механики добавляются расширением рил-машины: своими стратегиями движения, своим CellView, своей раскладкой или своим адаптером. Способы расширения описаны ниже, в разделах «Стратегии», «Раскладка и нестандартная сетка» и «Своё расширение».

Рил-машина состоит из двух частей. Ядро (src/core/reels/) — модель на TypeScript: состав и расчёт движения барабанов, данные раунда. Адаптер (src/engine/reels/) переносит состояние модели в дерево сцены PIXI.

Значения ячеек машина получает в данных раунда через setData. По ним она вычисляет позицию каждого барабана на каждом кадре: барабаны останавливаются так, что в ячейках оказываются значения из данных.

Время модель получает от вызывающего кода: тот вызывает advance(deltaFrames) на каждом кадре. Адаптер делает это из тикер-колбэка PIXI; без адаптера ядро работает в тестах, в расчётах длительности или под собственным рендером.

Схема композиции

Быстрый старт

Пример собирает машину из трёх барабанов с PIXI-адаптером и проводит один раунд: стартовая доска, прокрутка, посадка на результат.

import { Container, Sprite, Texture } from 'pixi.js'
import { ReelsMachine } from 'src/core/reels/reels-machine'
import { LinearSpinStrategy } from 'src/core/reels/strategies/linear-spin'
import { PlannedLandingStrategy } from 'src/core/reels/strategies/planned-landing'
import { ReelsView } from 'src/engine/reels/reels-view'
import type { CellView } from 'src/engine/reels/types'

type Grid = string[][] // [барабан][ряд]

// Модель: три барабана по три ряда, единица длины — ячейка
const machine = new ReelsMachine<Grid, string>({
  reels: [{ id: 'r0' }, { id: 'r1' }, { id: 'r2' }],
  rows: 3,
  cellHeight: 1,
  accessorFn: (data, { reel, row }) => data[reel]?.[row],
  getFillerValue: () => 'blank',
  spinStrategy: new LinearSpinStrategy({ speed: 0.3 }),
  landingStrategy: new PlannedLandingStrategy({
    speed: 0.3,
    deceleration: 0.01,
    handoverSpeed: 0.15,
    easeCells: 0.25,
    backStrength: 0.35,
    staggerCells: 2,
  }),
})

// View-компонент ячейки: адаптер вызывает оба метода на каждой синхронизации барабана
class SymbolView extends Container implements CellView<string> {
  private readonly sprite = new Sprite()
  private value: string | null = null

  constructor() {
    super()

    this.sprite.anchor.set(0.5) // (0, 0) CellView — центр ячейки
    this.addChild(this.sprite)
  }

  setValue(value: string): void {
    if (value === this.value) return

    this.value = value
    this.sprite.texture = Texture.from(value) // текстура из кэша Assets по алиасу
  }

  setMoving(moving: boolean): void {
    this.sprite.alpha = moving ? 0.6 : 1
  }
}

// Адаптер: ячейка модели — 200 px; advance на каждом кадре вызывает сам ReelsView
const reelsView = new ReelsView(app.ticker, machine, {
  cellWidth: 200,
  cellHeight: 200,
  createCellView: () => new SymbolView(),
})

app.stage.addChild(reelsView)

// Раунд: стартовая доска, прокрутка, посадка на результат
machine.setData([['A', 'B', 'C'], ['A', 'A', 'B'], ['C', 'B', 'A']])
machine.reset()

machine.spin()
machine.setData(await fetchRoundResult()) // результат раунда, например ответ сервера
await machine.land()

ReelsView ставит центр верхней ячейки барабана i в точку (cellWidth × i, 0) и отсчитывает маску от этой точки на половину ячейки вверх и влево. Поэтому точка (0, 0) CellView соответствует центру ячейки.

Путь от спина до посадки

Что происходит в модулях машины от вызова spin до остановки последнего барабана.

  1. Ваш код вызывает machine.spin(). ReelsMachine.spin вызывает Reel.spin у барабанов в фазе idle, кроме удержанных.
  2. Reel.spin фиксирует стратегии спина, делает текущим движением SpinMotion и переводит слоты в позу движения.
  3. На каждом кадре ReelsView вызывает machine.advance(deltaTime). Машина вызывает advance каждого барабана, барабан — advance своего движения.
  4. SpinMotion.advance сдвигает ленту на spinStrategy.step(...) через ReelStrip.moveTo. Перенесённые слоты получают значение наполнения.
  5. Затем в том же кадре ReelsView.sync сравнивает ревизии и для изменившихся барабанов вызывает ReelView.sync: тот задаёт каждому CellView барабана y, setValue и setMoving.
  6. Ваш код получает результат раунда и вызывает machine.setData(data) и machine.land(options).
  7. ReelsMachine.land выбирает барабаны в фазе spinning, вычисляет для каждого order и число пауз anticipation и вызывает Reel.land.
  8. Reel.land передаёт стратегии посадки LandingContext с числом кадров прокрутки spunFrames, получает LandingPlan и делает текущим движением LandingMotion.
  9. LandingMotion.advance берёт путь из plan.positionAt и вызывает ReelStrip.moveTo. Для каждого перенесённого слота Reel.fillLanding записывает значение ряда, где слот остановится.
  10. На последнем кадре плана LandingMotion выравнивает ленту snap(). Барабан снимает движение и резолвит свой промис, машина вызывает onReelLanded.
  11. Когда остановились все барабаны, промис machine.land резолвится.

Пункты 3 и 5 выполняются на каждом кадре до остановки барабана: на прокрутке кадр обрабатывает SpinMotion (пункт 4), на посадке — LandingMotion (пункт 9). Устройство кадра — в разделе «Кадр и единицы».

Руководства по ядру

Как устроен каждый модуль ядра и как он связан с соседними.

Данные раунда и конфиг

Машина создаётся из ReelsConfig один раз. Конфиг задаёт состав барабанов, геометрию, чтение данных раунда и стратегии по умолчанию. Поля — в API.

Данные раунда

Формат данных раунда выбирает ваш код. Ядро читает их только через accessorFn(data, { reel, row }): функция возвращает значение ячейки или undefined, если результата на ячейку нет.

type Grid = string[][] // [барабан][ряд]

const data: Grid = [['A', 'K', 'W'], ['S', 'A', 'A'], ['W', 'M', 'K']]
const accessorFn = (data: Grid, { reel, row }: CellIndex) => data[reel]?.[row]
// ячейка { reel: 1, row: 0 } → 'S'

Данные записывает machine.setData(data), начальные можно передать полем data конфига. Из данных читают reset, посадка, каскад и Cell.getValue. Посадка читает значение в момент переноса каждого слота, поэтому setData вызывается до land. Если accessorFn вернул undefined, слот останавливается со значением наполнения и позой движения.

Значение наполнения

getFillerValue(reel) отдаёт значение слота вне результата раунда. Машина вызывает её при создании машины, при каждом переносе слота на прокрутке и для ячейки без значения в данных.

Геометрия

  • rows — число видимых рядов.
  • buffer — число слотов над видимой зоной, по умолчанию DEFAULT_BUFFER = 1. Перенесённый слот получает новое значение в буфере, за маской.
  • cellHeight — высота ячейки, единица длины модели. Скорости и ускорения стратегий задаются в этих единицах.

Описание барабана

reels — массив ReelDef, по одному на барабан; индекс в массиве — индекс барабана. Поле id обязательно. Поля rows, buffer, accessorFn, spinStrategy, landingStrategy и fallStrategy перекрывают конфиг машины для одного барабана. cellHeight и getFillerValue общие для всех барабанов.

reels: [
  { id: 'r0' },
  { id: 'r1', rows: 4 },                      // барабан выше соседей
  { id: 'r2', landingStrategy: slowLanding }, // своя посадка
]

Метаданные барабана

ReelDef.meta хранит произвольные данные барабана. Ядро поле не читает, ваш код получает его через reel.def.meta. Тип расширяется аугментацией интерфейса ReelMeta:

declare module 'src/core/reels/types' {
  interface ReelMeta {
    readonly isBonusReel?: boolean
  }
}

Машина

ReelsMachine — точка входа ядра. Машина хранит данные раунда и стратегии по умолчанию, создаёт барабаны по конфигу и передаёт им вызовы раунда. Методы — в API.

Что машина вычисляет

  • order посадки — порядковый номер барабана среди барабанов в фазе spinning. Удержанные барабаны в счёт не входят.
  • order каскада — порядковый номер среди барабанов, в которых есть ячейки из removed.
  • anticipationPauses — число индексов из anticipation, не больших индекса барабана; isAnticipating — индекс барабана есть в списке.
  • Фазу машины: landing, spinning или falling — первая по этому порядку фаза, которая есть хотя бы у одного барабана; иначе idle.

Промисы и колбэки

land и cascade возвращают промис, который резолвится после остановки всех участвующих барабанов. onReelLanded(reel) машина вызывает после резолва промиса барабана — в микрозадаче после того advance, на котором барабан остановился. onReelAnticipated(reel) вызывается синхронно внутри advance, в кадре начала паузы.

Промотка по сигналу

slamSignal в опциях land и cascade — AbortSignal. Если сигнал сработал до вызова, машина вызывает slam() сразу после запуска движений; если по ходу движения — в момент срабатывания. После конца движения машина снимает подписку на сигнал.

Барабаны, ячейки, ряды

Reel создаёт машина по ReelDef. У барабана rows ячеек, лента из rows + buffer слотов и одно текущее движение.

cell.getValue() возвращает значение из данных раунда, cell.getSlot() — слот, который стоит в ячейке сейчас. На прокрутке getValue() уже возвращает результат раунда, а getSlot() — слот со значением наполнения. После посадки значения совпадают.

getSlot() ищет слот по текущим позициям через getVisibleSlotIndices(). На прокрутке и после каскада по одному адресу оказываются разные слоты.

Ряды и сетка

machine.getRows() возвращает Row на каждый ряд из config.rows; row.getCells() — ячейки ряда слева направо, барабан без такого ряда пропускается. machine.getGrid() возвращает ячейки по барабанам, [барабан][ряд]; machine.getCell({ reel, row }) — одну ячейку.

Контекст ячейки

cell.getContext() собирает машину, барабан, ячейку и функцию getValue в один объект CellContext. Его передают в функции, которым нужна ячейка вместе с барабаном и машиной.

Лента и слоты

ReelStrip хранит слоты барабана, базу каждого слота и путь ленты. Позиции слотов меняет только ReelStrip, значения слотов записывает Reel.

stripHeight   = (rows + buffer) × cellHeight

позиция i     = wrapOffset(база i + путь ленты)       диапазон [−buffer × cellHeight, rows × cellHeight)

Перенос слота

moveTo(offset, onWrap) задаёт путь ленты и пересчитывает позиции всех слотов из одного числа, поэтому погрешность между слотами не накапливается. Для каждого слота ReelStrip вычисляет номер круга getLap. Если номер изменился, слот перенесён, и moveTo вызывает onWrap(slot). Номер круга меняется при переходе границы в обе стороны, поэтому ленту можно двигать и вверх.

Что записывает onWrap, определяет текущее движение: на прокрутке — значение наполнения, на посадке — значение ряда, в котором слот остановится.

Ревизия

Каждый вызов moveTo, place, rebase и touch увеличивает ревизию ленты. Reel.getRevision() отдаёт её адаптеру: барабан с прежней ревизией адаптер не перерисовывает. touch() Reel вызывает после записи значений или поз в обход методов ленты — в reset и spin.

Выравнивание и базы

  • snap() в конце посадки округляет путь и позиции слотов до границ ячеек. Позы слотов snap не меняет.
  • place(slotIndex, position) ставит слот на позицию без приведения к диапазону ленты. Им пользуется падение каскада: у каждого падающего слота свой путь.
  • rebase() после падения записывает текущие позиции слотов в базы и обнуляет путь: порядок слотов на ленте после каскада отличается от исходного.

У барабана одно текущее движение ReelMotion или null. Фаза барабана равна motion.phase, без движения барабан в фазе idle. Reel.advance передаёт шаг движению и снимает его, когда isDone() возвращает true; промис land или cascade при этом резолвится.

Кадр и единицы

Своего таймера у модели нет. Вызывающий код продвигает её вызовом machine.advance(deltaFrames) один раз за кадр. Адаптер делает это из тикер-колбэка и затем переносит изменившиеся барабаны в CellView.

Единицы

Длина измеряется в единицах cellHeight модели. Адаптер переводит их в пиксели множителем ReelsViewConfig.cellHeight / ReelsModel.cellHeight. Модель с cellHeight: 1 считает в ячейках; в pixi-demos обе высоты заданы в пикселях, множитель равен 1.

Время измеряется в кадрах: deltaFrames = 1 соответствует одному кадру при 60 fps, как Ticker.deltaTime у PIXI. Скорости стратегий заданы в единицах длины за кадр, ускорения — в единицах за кадр². На 120 Гц шаг вдвое короче, кадров вдвое больше, длительность движения в секундах та же.

Как слот получает финальное значение

План посадки известен целиком с первого кадра: plan.distance — полный путь ленты, plan.positionAt(elapsed) — пройденный. На каждом кадре LandingMotion передаёт в колбэк переноса остаток пути remaining = distance − positionAt(elapsed).

Позиция остановки перенесённого слота равна его текущей позиции плюс остаток пути. Reel.fillLanding вычисляет по ней ряд:

  • позиция не меньше rows × cellHeight — слоту предстоит ещё один круг, он получает значение наполнения;
  • иначе слот получает значение ряда round(позиция / cellHeight) из данных раунда и позу покоя.

Путь посадки включает не меньше одного оборота ленты, поэтому каждый слот переносится хотя бы раз и на последнем обороте уже показывает значение из данных раунда. slam() меняет только время движения, план остаётся прежним, поэтому после промотки слоты получают те же значения.

Стратегии

Стратегия — объект с одним методом. Машина получает стратегии из конфига или setStrategies, барабан фиксирует набор в начале спина. Стратегия из ReelDef перекрывает стратегию машины.

Контекст

ReelContext — геометрия барабана: index, rows, buffer, cellHeight, stripHeight. LandingContext добавляет order, fromOffset, spunFrames, anticipationPauses и isAnticipating. FallContext добавляет order и drops — падающие слоты с рядом назначения и путём до него.

План

  • totalFrames — длительность движения в кадрах.
  • settleFrames — начало финального участка. slam переводит время движения к этому кадру. Стратегия без финального участка отдаёт totalFrames, и по slam барабан останавливается на следующем кадре.
  • LandingPlan.positionAt(frames) — путь ленты от начала посадки; FallPlan.positionAt(drop, frames) — путь слота drops[drop].
  • LandingPlan.distance — полный путь ленты до остановки; из него вычисляется остаток пути для перенесённых слотов.
  • LandingPlan.anticipationFrames — кадр начала собственной паузы anticipation; в этом кадре барабан вызывает onAnticipated.

Требования к стратегии посадки

  • positionAt(totalFrames) равен distance.
  • fromOffset + distance кратно cellHeight. На последнем кадре snap() округляет путь до границы ячейки, расхождение даст скачок барабана. Недостающий путь вычисляет getAlignmentGap.
  • distance не меньше stripHeight. Слот, не перенесённый за посадку, сохранит значение наполнения.

Требования к стратегии падения

  • positionAt(drop, totalFrames) равен drops[drop].distance. Иначе на последнем кадре слот переместится на ряд скачком.
  • Слот выше падает не быстрее соседа снизу, иначе слоты перекроются.

Готовые стратегии — LinearSpinStrategy, PlannedLandingStrategy и GravityFallStrategy. Опции — в API, устройство и настройки слота — в «Стратегиях слота».

Инварианты

  • Один вызов advance на кадр. Второй адаптер или второй цикл над той же моделью продвинет её дважды за кадр.
  • Позиции меняет ReelStrip, значения — Reel. Значения слотам Reel записывает в колбэке переноса, в reset и в cascade.
  • Порядок getStrip() постоянен. Адаптер хранит CellView по индексу из getStrip(). Порядок getVisibleSlotIndices() пересчитывается по позициям на каждом вызове.
  • Граница диапазона ленты. Точка покоя слота может попасть ровно на верхнюю границу диапазона, и сторону результата % определяет ошибка округления: слот оказывается под видимой зоной, соответствие «слот → ряд» сдвигается на единицу. wrapOffset и getLap применяют одинаковый допуск WRAP_EPSILON. Регрессию проверяет strip-wrap.test.ts.
  • snap() не меняет позы. Позу покоя слот получил при последнем переносе; повторная смена позы сбросила бы idle-анимацию CellView.
  • После падения базы переписываются. Без rebase() первый сдвиг ленты вернул бы слоты на прежние места.
  • Адаптер пропускает барабаны с прежней ревизией. Пока барабан стоит, ваш код может временно перенести его CellView в другой контейнер, и адаптер их позиции не перезаписывает.
Механики

Каждый раздел: что видит игрок, какие методы и опции участвуют, какие требования предъявляются к данным раунда.

Спин и посадка

Игрок нажимает Spin: все барабаны крутятся, затем по очереди останавливаются на символах результата.

machine.spin()           // барабаны в idle переходят в spinning
// ... ваш код получает результат раунда
machine.setData(result)
await machine.land({ onReelLanded: (reel) => playStopSound(reel) })

spin запускает прокрутку барабанов в фазе idle и фиксирует для каждого текущие стратегии. land сажает барабаны в фазе spinning. Между spin и land барабаны крутятся без ограничения по времени: момент посадки выбирает ваш код.

reset() ставит стоящие барабаны на текущие данные без анимации: стартовая доска или возврат после отмены.

Stagger

Барабаны останавливаются слева направо с интервалом. Машина передаёт стратегии посадки order — порядковый номер барабана среди садящихся. PlannedLandingStrategy добавляет к пути order × staggerCells ячеек. Удержанные барабаны в счёт не входят: первый крутящийся барабан получает order = 0.

В каскаде order — номер среди падающих барабанов; GravityFallStrategy сдвигает их старт на order × staggerFrames кадров.

Другой порядок остановки — справа налево, от центра — задаёт своя стратегия посадки: ей доступны order и index из контекста. Пример — «Своё расширение».

Минимум вращения

Спин длится не меньше заданного времени, даже если land вызван сразу после spin. SpinMotion считает кадры прокрутки, Reel.land передаёт их стратегии в spunFrames. PlannedLandingStrategy с опцией minSpinFrames удлиняет равномерный участок на max(0, minSpinFrames − spunFrames) кадров. Если land вызван позже минимума, путь не удлиняется.

Anticipation

Барабан, который может дать бонус, крутится дольше остальных; барабаны правее него останавливаются после него.

await machine.land({
  anticipation: [3, 4],
  onReelAnticipated: (reel) => glow.show(reel),
  onReelLanded: (reel) => glow.hide(reel),
})
  • Барабан получает anticipationPauses — число индексов из anticipation, не больших своего. Барабан 4 при anticipation: [3, 4] получает две паузы: одну за барабаном 3 и свою.
  • isAnticipating — барабан сам есть в списке. Собственная пауза и вызов onReelAnticipated есть только у такого барабана.
  • PlannedLandingStrategy добавляет anticipationPauses × anticipationCells ячеек к равномерному участку и отдаёт anticipationFrames — кадр, в котором барабан остановился бы без собственной паузы.
  • onReelAnticipated вызывается синхронно внутри advance, в кадре anticipationFrames. Конец паузы — onReelLanded того же барабана.
  • Пауза входит в равномерный участок, поэтому slam проматывает её вместе с ним. О промотанной паузе onReelAnticipated не сообщает: slam переносит время вне advance.

Slam stop

Игрок нажимает Stop во время посадки: барабаны сразу переходят к финальному отскоку и останавливаются одновременно.

const stop = new AbortController()

stopButton.onTap = () => stop.abort()

await machine.land({ slamSignal: stop.signal })

По slamSignal машина вызывает slam() каждого барабана, барабан — текущего движения. Посадка и падение переводят время к settleFrames, план не меняется. SpinMotion на slam не реагирует: у прокрутки нет финального участка. Сигнал, сработавший до вызова land, машина применяет сразу после запуска посадки.

machine.slam() можно вызвать и напрямую.

Отмена

signal в опциях land и cascade отменяет движение: барабан снимает движение, промис отклоняется с signal.reason. Барабан останавливается в позиции на момент отмены и переходит в idle. reset() возвращает барабаны на данные раунда.

У spin сигнала нет: прокрутка продолжается до land. Чтобы остановить барабаны без нового результата, ваш код передаёт в setData прежние данные и вызывает land. Так игра обрабатывает ошибку запроса, см. «Slam stop в игре».

Удержанные барабаны

Барабан с вайлдом стоит, остальные крутятся заново. spin({ held: [2] }) не запускает барабан 2: он остаётся в idle со слотами прошлого раунда. land сажает только крутящиеся барабаны, order считается без удержанных.

Данные раунда обязаны повторять значения удержанных барабанов. Cell.getValue() удержанной ячейки читает новые данные, а на экране стоят слоты прошлого раунда.

Каскад

Выигравшие символы исчезают, уцелевшие падают вниз на освободившиеся ряды, сверху падают новые.

const exploded = removed.map((cell) => reelsView.getCellView(cell)) // до вызова cascade

machine.setData(nextGrid)
await machine.cascade({ removed })
  1. Машина выбирает барабаны, в которых есть ячейки из removed; order — порядковый номер среди них.
  2. Уцелевшие слоты сохраняют порядок и опускаются на число убранных рядов под ними. Слот, чей ряд не изменился, остаётся на месте.
  3. Слоты убранных ячеек получают значения новых верхних рядов 0..k−1 из данных раунда, выстраиваются столбиком над видимой зоной и падают на k ячеек. Буферный слот не двигается.
  4. FallMotion двигает каждый слот по своему пути из FallPlan через place, без приведения к диапазону ленты. Значения на падении не меняются.
  5. На последнем кадре слоты становятся точно на ряды, rebase() записывает позиции в базы и обнуляет путь. Следующий спин считает позиции от новых баз.
  • Уцелевшие слоты сохраняют свои значения, поэтому данные раунда обязаны повторять их на новых рядах.
  • Каскад запускается только у барабанов в idle; у движущегося барабана промис резолвится сразу.
  • Без fallStrategy в конфиге, в ReelDef или в setStrategies промис cascade отклоняется с ошибкой Reel <id> has no fall strategy.
  • cascade переставляет слоты синхронно внутри вызова. CellView убранных ячеек нужно получить через getCellView до вызова: после него по тем же адресам стоят другие слоты.

Смена стратегий

Турбо-режим ускоряет вращение барабанов и сокращает stagger. machine.setStrategies(strategies) заменяет стратегии машины по умолчанию; барабан берёт их в следующем spin, текущая посадка не меняется.

machine.setStrategies(isTurbo ? TURBO_STRATEGIES : NORMAL_STRATEGIES)

Стратегии из ReelDef перекрывают стратегии машины и после setStrategies.

Скорость SpinStrategy обязана совпадать со скоростью равномерного участка LandingStrategy, иначе на входе в посадку скорость барабана меняется скачком. Поэтому набор собирается фабрикой с одной скоростью на обе стратегии — пример createStrategies в «Стратегиях слота».

Раскладка и нестандартная сетка

  • По умолчанию ReelsView ставит центр верхней ячейки барабана i в точку (cellWidth × i, 0). Функция getReelPosition(index) в ReelsViewConfig задаёт другую раскладку.
  • Барабаны с одинаковым y делят одну маску-полосу. Маска PIXI 8 — stencil: она прерывает батч и рисуется дважды, поэтому ReelsView создаёт по маске на полосу раскладки.
  • Высоту отдельного барабана задаёт ReelDef.rows. Маска полосы получает высоту самого высокого барабана полосы.
  • Поле, в котором каждая ячейка крутится отдельно, собирается из барабанов высотой 1. accessorFn переводит индекс барабана в адрес ячейки ваших данных, getReelPosition ставит барабаны сеткой. Пример — Hold & Win.
  • Скрытый ReelsView (visible = false) масок не рисует.

Своё расширение

Своя стратегия

Стратегия реализует контракт из types.ts и передаётся в конфиг, в ReelDef или в setStrategies. Пример — остановка справа налево поверх готовой посадки:

class RightToLeftLanding implements LandingStrategy {
  private readonly inner: LandingStrategy
  private readonly reelCount: number

  constructor(inner: LandingStrategy, reelCount: number) {
    this.inner = inner
    this.reelCount = reelCount
  }

  plan(context: LandingContext): LandingPlan {
    // Правый барабан получает order = 0 и останавливается первым
    return this.inner.plan({ ...context, order: this.reelCount - 1 - context.order })
  }
}

const landingStrategy = new RightToLeftLanding(new PlannedLandingStrategy(options), 5)

SpinStrategy может возвращать отрицательный шаг: номер круга меняется при переходе границы в обе стороны, и барабан крутится вверх. Готовая PlannedLandingStrategy рассчитана на движение вниз.

Свой CellView

CellView — PIXI-контейнер с методами setValue(value) и setMoving(moving). Адаптер задаёт ему y и вызывает оба метода на каждой синхронизации барабана, поэтому повторный вызов с тем же аргументом не должен ничего менять. Другие позы — выигрыш, взрыв — ставит ваш код через getCellView; setMoving может их сохранять, так сделано в ReelSymbol.

Свой адаптер

Адаптер для другого рендера — Canvas 2D, DOM, другого движка — строится над контрактом ReelsModel:

  1. На каждом кадре вызвать model.advance(deltaFrames) один раз.
  2. Для барабанов из getReels() сравнить getRevision() с последней отрисованной; при полной перерисовке кадра этот шаг не нужен.
  3. Для изменившегося барабана пройти getStrip(): слот i рисуется элементом i, позиция — slot.offset × масштаб, значение — slot.value, поза — slot.moving.
  4. Обрезать каждый барабан по видимой зоне высотой rows × cellHeight: буферные слоты лежат выше неё.
  5. Элемент по адресу ячейки — слот с индексом getVisibleSlotIndices()[row].
const CELL_PX = 120
const scale = CELL_PX / model.cellHeight

const draw = (): void => {
  ctx.clearRect(0, 0, canvas.width, canvas.height)

  model.getReels().forEach((reel, index) => {
    ctx.save()
    ctx.beginPath()
    ctx.rect(index * CELL_PX, 0, CELL_PX, reel.rows * CELL_PX)
    ctx.clip()

    for (const slot of reel.getStrip()) {
      ctx.fillText(String(slot.value), index * CELL_PX + CELL_PX / 2, slot.offset * scale + CELL_PX / 2)
    }

    ctx.restore()
  })
}

let last = performance.now()

const frame = (now: number): void => {
  model.advance((now - last) / (1000 / 60)) // кадры при 60 fps
  last = now
  draw()
  requestAnimationFrame(frame)
}

Как работает адаптер

ReelsView — PIXI-Container. Конструктор получает тикер, модель и ReelsViewConfig и выполняет шаги:

  1. Вычисляет unitScale = config.cellHeight / model.cellHeight.
  2. Создаёт ReelView на каждый барабан модели, в нём — по CellView на слот ленты через createCellView.
  3. Ставит центр верхней ячейки барабана i в точку getReelPosition(i), по умолчанию (cellWidth × i, 0).
  4. Группирует барабаны с одинаковым y в полосу и накрывает её одной маской: по ширине — от левого барабана до правого плюс половина ячейки с каждой стороны, по высоте — rows × cellHeight самого высокого барабана полосы, от y − cellHeight / 2.
  5. Переносит слоты в CellView и добавляет колбэк step в тикер.

На каждом кадре step вызывает model.advance(ticker.deltaTime), затем sync. sync сравнивает ревизию каждого барабана с последней отрисованной и для изменившихся вызывает ReelView.sync: тот задаёт каждому CellView барабана y = slot.offset × unitScale, setValue(slot.value) и setMoving(slot.moving).

  • Точка (0, 0) CellView — центр ячейки.
  • getCellView({ reel, row }) находит CellView по текущим позициям слотов. На прокрутке и после каскада по одному адресу оказываются разные CellView.
  • Пока ревизия барабана не изменилась, адаптер его CellView не трогает. Ваш код может временно перенести CellView стоящего барабана в другой контейнер — например, поднять выигравший символ над затемнением — и вернуть до следующего движения.
  • Над одной моделью — один ReelsView: каждый экземпляр вызывает advance.
  • destroy() снимает step с тикера и уничтожает контейнер вместе с CellView.

Стратегии слота

createStrategies в games/slot/reels.ts собирает набор из трёх стратегий с одной скоростью SPIN_SPEED × speedFactor для LinearSpinStrategy и равномерного участка PlannedLandingStrategy. Ускорения растут квадратом множителя, интервалы падения делятся на него. Длины заданы в пикселях зоны символов, высота ячейки — 610 / 3 px.

Посадка PlannedLandingStrategy

путь = оборот ленты + недокрученный минимум вращения + order × staggerCells
       + anticipationPauses × anticipationCells + тормозной путь + путь отскока + добор до границы ячейки

  скорость
     speed ├──────────────┐
           │  равномерно   \  линейное торможение
  handover │                \────┐
           │                     │  отскок easeOutBack
         0 └─────────────────────┴──── кадры
  • Оборот ленты в пути: каждый слот переносится хотя бы раз и получает значение из данных раунда.
  • Добор до границы ячейки делает fromOffset + путь кратным высоте ячейки: барабан останавливается ровно на границе ячейки.
  • Паузы anticipation лежат на равномерном участке, slam проматывает их вместе с ним.
  • Длительность отскока подобрана по производной easeOutBack в нуле: скорость на входе в отскок равна handoverSpeed, скачка скорости нет. Точка промотки — начало отскока.

Кадры ниже посчитаны PlannedLandingStrategy с настройками SLOT_STRATEGIES: land вызван на 40-м кадре прокрутки с anticipation: [3, 4].

Падение GravityFallStrategy

старт слота = order × staggerFrames + (нижний ряд падения − ряд слота) × rowStaggerFrames
путь слота  = gravity × t² / 2 до касания ряда, затем отскок на bounceCells за bounceFrames

Нижний слот барабана стартует первым, слот выше падает не меньше соседа снизу, поэтому слоты не перекрываются. Точка промотки — кадр касания последнего слота.

Anticipation в игре

Список барабанов с паузой приходит в ответе сервера и лежит в сторе как presentedAnticipation. Контроллер передаёт в land колбэки: onReelAnticipated показывает рамку AnticipationGlowFrame и эмитит reel:anticipationStarted, onReelLanded прячет рамку и эмитит reel:landed. На оба события подписан звук.

await this.machine.land({
  signal,
  slamSignal: stopSignal,
  anticipation,
  onReelLanded: this.handleReelLanded,
  onReelAnticipated: this.handleReelAnticipated,
})

Slam stop в игре

Кнопка спина во время движения эмитит ui:stopRequested. Фаза spinning превращает событие в сигнал stopSignal через emitter.signalOn и передаёт его аргументом reels.land(...); контроллер передаёт сигнал в машину как slamSignal. Подписку снимает scope.abort() в конце фазы.

const scope = new AbortController()
const stopSignal = this.emitter.signalOn('ui:stopRequested', {
  signal: scope.signal,
  filter: () => this.slotStore.canStop,
})

try {
  // ...
  await this.reels.land(this.slotStore.spinSymbols, this.slotStore.presentedAnticipation, signal, stopSignal)
} finally {
  scope.abort()
}

При ошибке запроса фаза сажает барабаны на доску до спина тем же land и возвращает раунд в idle: так останавливается прокрутка без нового результата.

Респин

Шаг респина в ответе сервера содержит индексы удержанных барабанов. Фаза respin вызывает reels.spin(step.held) и reels.land(stepSymbols, []); контроллер передаёт held в machine.spin({ held }). Данные шага повторяют символы удержанных барабанов. Рамку удержания рисует HeldFrameController по heldReels из стора.

Каскад в игре

Фаза cascade вызывает reels.explode(removed) — символы убранных ячеек проигрывают взрыв — затем reels.cascade(frame, removed).

// CellView взорванных ячеек берутся до каскада: модель переставит слоты
const exploded = removed.flatMap((cell) => this.board.getCellView(cell) ?? [])

this.machine.setData(symbolKeys)

const falling = this.machine.cascade({ removed, signal, slamSignal: stopSignal, onReelLanded: this.handleReelLanded })

// Слоты уже подняты над зоной: адаптер перенесёт позиции раньше, чем кадр отрисуется
exploded.forEach((symbol) => symbol.idle())

await falling

Hold & Win

Бонус использует вторую машину на тех же классах: 15 барабанов высотой 1, по одному на ячейку поля 5×3.

export const HOLD_WIN_REELS: ReelsConfig<HoldWinReelsData, HoldWinCell> = {
  reels: Array.from({ length: HOLD_WIN_CELLS_COUNT }, (_, index) => ({ id: `cell-${index}` })),
  rows: 1,
  buffer: BUFFER_SYMBOLS_COUNT,
  cellHeight: CELL_HEIGHT,
  accessorFn: (data, { reel }) => {
    const cell = toHoldWinCell(reel) // барабан reel × 3 + row → ячейка { reel, row } поля

    return data[cell.reel]?.[cell.row]
  },
  getFillerValue: () => getRandomSymbolKey(),
  ...HOLD_WIN_STRATEGIES,
}

export const getHoldWinReelPosition = (index: number): PointData => {
  const { reel, row } = toHoldWinCell(index)

  return { x: CELL_WIDTH * reel, y: CELL_HEIGHT * row }
}
  • getReelPosition ставит барабаны сеткой в тех же координатах, что ячейки основной доски. Барабаны одного ряда поля имеют одинаковый y и делят маску: 15 барабанов рисуют три маски.
  • CellView бонуса — Coin: номинал монеты или символ наполнения.
  • Удержанные монеты передаются в spin({ held }) индексами барабанов через toHoldWinReel.
  • Контроллеры меняют доски вызовами show / hide; скрытая доска не рисует масок.

Интеграция в игру

Окружение

  • Конечный автомат фаз (core/fsm). Фаза — класс с методом enter(signal): выполняет свою часть раунда и возвращает имя следующей фазы. Фазы слота — в games/slot/phases/.
  • Стор (stores/slot.ts) — класс MobX с ответом сервера. Пишут в него только фазы; геттеры spinSymbols, nextCascade, heldReels извлекают данные текущего шага.
  • Контроллер — наследник LiveContainer. Подписки на стор оформлены через this.watch и снимаются при destroy. Фазы вызывают методы контроллеров и ждут их промисы.
  • Эмиттер — типизированные события игры. Контроллеры объявляют через него моменты раунда, звук на них подписан.
  • DI (inversify) создаёт фазы, стор и контроллеры верхнего уровня; вложенные контроллеры создаёт владелец через new. Подробнее — CLAUDE.md.

Фазы раунда

Фазы импортируют контроллеры только как типы и к ядру и адаптеру не обращаются. Следующую фазу выбирает текущая по данным ответа в сторе: есть ли следующий шаг каскада, респина или бонуса.

Спин по шагам

Фаза spinning запускает прокрутку и запрос одновременно: барабаны крутятся, пока идёт запрос, и после ответа сервера фаза сажает барабаны на присланные символы.
