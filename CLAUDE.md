## Обзор

Пет-проект для изучения PIXI.js и геймдева. Цель — слот-машина.

**Статус** Сквозной спин работает: кнопка → сеть → сторы → контроллеры → скелеты. Барабаны
крутятся и садятся на серверные символы, счёт ведётся по данным сервера, линии выплат рисуются,
ошибки доходят до игрока. Есть slam stop и турбо-режим: быстрый спин по тапу, серия по удержанию.
Есть респин по липкому вайлду: барабан с W удерживается, остальные крутятся заново.
Есть бонус Hold & Win: три скаттера ставят монеты на поле из 15 барабанов высотой 1, монеты
удерживаются, пустые ячейки крутятся, пока не кончится счётчик респинов.
Есть каскады: выигравшие символы взрываются, уцелевшие падают вниз, сверху падают новые; цепочка идёт,
пока в кадре есть выигрыш, множитель выигрыша растёт с каждым шагом.
Звук — синтезированные SFX по моментам игры, без аудиоассетов.

**Вторая игра — toybox**, автомат с игрушками: изометрическая сетка под кубом, клешня ходит по её осям
и достаёт игрушку в лоток. Арт — покадровая пиксель-арт анимация, кадры из Aseprite; стек тот же, что
у слота, без сетевых библиотек. Сквозной цикл работает: джойстик водит каретку по полю, кнопка опускает
клешню на верх стопки под ней, захват удаётся с вероятностью, и клешня может выронить игрушку — на
подъёме или по дороге к лотку; та падает и отскакивает по соседним ячейкам, пока не осядет.
Клешня висит под кареткой на тросе и качается: вес в движении имитируется затухающей пружиной, а не
физическим движком. Куб поделён по высоте на слои:
куча сложена куполом, стопка ограничена по высоте, а лоток отгорожен от куба стенками ниже её предела,
поэтому игрушка переваливается в лоток только сверху. Поднятая игрушка оставляет провал, и куча
осыпается в него. Доставленная в лоток игрушка уходит в счётчик.
Прод-сборка показывает на странице игры заглушку, канвас открывается флагом `?play`.

**Стек:** React 19 · PIXI.js v8 · MobX 6 · inversify 8 · Tailwind CSS v4 · react-router-dom v7 ·
TypeScript 6 · Vite 8; сеть — zod + partysocket, моки — MSW, скелеты — стаб из `engine/skeleton`,
звук — Web Audio API без библиотек (`engine/audio`); монорепо — pnpm workspaces + Turborepo.
Рантайм `@esotericsoftware/spine-pixi-v8` остаётся в зависимостях, но сейчас не импортируется:
Spine-ассеты лицензионные и в репозиторий не попадают. Версия пинована тильдой `~4.2.x` —
major.minor рантайма обязан совпадать с версией редактора, экспортировавшего ассеты (4.2.43).
React Compiler включён для JSX-файлов
(babel не парсит декораторы в `.ts`, см. [web/vite.config.ts](web/vite.config.ts)).

## Команды

| Команда                              | Что делает                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------ |
| `pnpm dev`                           | Vite dev-сервер приложения                                                     |
| `pnpm build`                         | typecheck всех пакетов + `vite build`                                          |
| `pnpm lint`                          | `eslint --quiet --fix .` + `tsc -b` по пакетам и eslint корневых конфигов      |
| `pnpm lint:ci`                       | то же без `--fix` — версия для CI                                              |
| `pnpm preview`                       | превью прод-сборки                                                             |
| `pnpm preview:mocks`                 | сборка с `VITE_USE_MOCKS=true` + превью — прод-сборка с работающими MSW-моками |
| `pnpm test`                          | vitest всех пакетов: модульные тесты и сценарии раунда                         |
| `pnpm coverage`                      | vitest с покрытием (v8), по пакетам                                            |
| `pnpm e2e`                           | сборка с моками, затем Playwright всех пакетов со спеками                      |
| `pnpm e2e --filter=@pixi-demos/slot` | то же для одной игры                                                           |

Задачи пакетов запускает Turborepo ([turbo.jsonc](turbo.jsonc)) и кэширует по хэшу входов: задача с
прежними входами повторно не выполняется. Задача без скрипта `transit` включает в хэш исходники
пакетов, от которых пакет зависит: правка `src` пакета сбрасывает кэш задач у зависимых пакетов.
Тесты пакета в этот хэш не входят. Корневой `package.json` не зависит от workspace-пакетов: исходники
пакетов, от которых зависит корень, turbo включает в глобальный хэш.

Husky `pre-commit` запускает `pnpm lint`; тесты и E2E гоняет CI. E2E в хук не заведены: им
нужны прод-сборка и браузер, для pre-commit это слишком долго.

## Деплой

Прод-хостинг — Netlify, сборку и публикацию ведёт GitHub Actions
([.github/workflows/ci.yml](.github/workflows/ci.yml)).

- **Деплой только из `main` и только после зелёных `checks` и `e2e`.** Релизом служит мёрдж PR;
  второй вход — кнопка Run workflow на `main`, она гоняет те же проверки перед деплоем.
  Джоб деплоя забирает артефакт `dist` (`web/dist`) из джоба e2e, поэтому публикуется проверенная сборка.
- **Кэш Turborepo сохраняется между запусками workflow** (`actions/cache`, `.turbo/cache`): задачи с
  прежним хэшем входов повторно не выполняются, браузеры Playwright устанавливаются, только если у
  какой-то задачи e2e нет записи в кэше. При ручном запуске workflow turbo получает `--force` и
  выполняет все задачи без кэша.
- **Бэкенда нет**: прод собирается `pnpm build:mocks`. MSW перехватывает WebSocket в самой
  странице, поэтому демо целиком статическое.
- **`VITE_WS_URL` задан в `.env` в корне репозитория.** Значение не секрет: его перехватывает мок, и оно
  обязано совпадать у транспорта и у хендлера; `envDir` приложения и тестов указывает на корень.
  `.env.local` переопределяет его локально.
- **Правила раздачи — `web/public/_redirects` и `web/public/_headers`.** Actions публикует готовый каталог,
  поэтому правила обязаны попасть в `dist/` вместе с ассетами. SPA-фолбэк обязателен:
  `createBrowserRouter` без него отдаёт 404 на `/slot` и на перезагрузку страницы.

## Архитектура

### Слои и направление импортов

Каждая папка в `packages/`, `games/` и `web/` — **workspace-пакет** со своим `package.json`,
зависимостями и тестами. Пакеты разделены по рантайму: чистый TS, zod, React, PIXI. Новые пакеты
добавляются в `games/`; приложение в репозитории одно.

```
packages/
  core/                чистый TS: errors/, events/, fsm/ (движки), palette, easing, random, storage, tokens
  net/                 транспорт WS и его биндинг, конверт, msw-хелпер; без PIXI и React
  engine/              PIXI-рантайм: хост, тикер, пул скелетов, skeleton/, синтезатор audio/
                       и базы сцены — LiveContainer и SpineAnimation
  reels/               модель рил-машины — самостоятельная библиотека без зависимостей
  reels-pixi-adapter/  PIXI-адаптер рил-машины
games/
  slot/                сама игра: api/ stores/ phases/ scenes/ mocks/ + листовые tokens, types,
                       constants, events, assets, utils, skeletons, reels, sounds; ui/ и controllers/
                       внутри разбиты по зонам сцены: hud/ и reels/
  toybox/              автомат с игрушками: bindings, stores/ phases/ scenes/ + листовые tokens,
                       types, constants, events, utils; ui/ и controllers/ внутри разбиты
                       по зонам сцены: box/ и hud/
web/                   приложение
  src/main.tsx         вход; сюда же подключён styles/index.css
  src/app/             composition root: контейнеры, биндинги, роутер, провайдеры
  src/pages/           роут-страницы; каждая — граница ленивого чанка
  src/components/      React-кит: Layout, Button, Snackbars, RouteError, BackgroundCanvas,
                       GameCanvas, GameTile, ApiProvider, icons/
  src/styles/          глобальный стиль и @theme-токены Tailwind
  public/              статика и ассеты игр
```

Код пакета лежит в его `src/`, тесты — в `tests/`, e2e игры и приложения — в `e2e/`.

- Граф импортов односторонний, `import/no-cycle` включён.
- **Направление между пакетами** задают их `package.json`: pnpm не резолвит незаявленный пакет,
  `import/no-extraneous-dependencies` сообщает о нём ошибкой линта. Ограничения, которых в
  `package.json` нет, проверяет ESLint (`@typescript-eslint/no-restricted-imports` с
  `allowTypeImports`, блок `files:` на пакет):

  ```
  core                →  ничего;                        запрещены pixi.js и react
  net                 →  core;                          запрещены pixi.js и react
  engine              →  core;                          запрещён react
  reels               →  ничего;                        независимая библиотека, запрещены pixi.js и react
  reels-pixi-adapter  →  reels;                         pixi.js — peerDependency
  games/*             →  core, net, engine, reels, reels-pixi-adapter;  никогда друг в друга
  web: components     →  core, net;                     PIXI только динамическим import()
  web: pages/*        →  всё; из игры — только её контракт
  web: app            →  всё, кроме games (пакет игры импортируют только её страница и агрегатор моков)
  ```

  Предел правил: относительный путь `../..` за границу пакета ни одно из них не проверяет, поэтому
  между пакетами импорт идёт только по имени пакета.
  Правя блоки, помни: в flat-config правила одного имени **заменяются целиком, а не складываются**,
  поэтому блок слоя обязан повторить пакетный набор — иначе он его молча снимет.

- **Токены — по пакету**: `CORE_TOKENS`, `NET_TOKENS`, `ENGINE_TOKENS`, `SLOT_TOKENS`. Каждый файл
  токенов — **лист графа**: в рантайме только `Symbol`, все классы — `import type` (иначе появятся
  циклы с композицией). `core/errors/` — тоже лист, его импортирует кто угодно.
- **`engine/skeleton/`** — реализация `SkeletonLike` по умолчанию: пока нет Spine-ассетов, скелеты
  рисует стаб. Описания скелетов приносит игра конфигом `SpinePoolConfig`, не сам движок.
- `phases/` вызывает `api/`, пишет в `stores/`, дёргает контроллеры сцены.
- **`phases/` и сцена обмениваются только `import type`**, экземпляры приходят через DI: в рантайме
  зависимости нет. Вверх сцена сообщает событиями, вниз принимает вызовы методов.

### Уровни внутри игры

Вниз импортировать можно, вверх — только `import type`; проверяется тем же правилом по путям
`#src/<уровень>`:

```
types/constants/tokens/assets/sounds  ←  лист
api          →  лист
stores       →  api, лист
phases       →  stores, api, лист;   controllers — только type
scenes       →  controllers, ui, лист
controllers  →  ui, stores, events, лист;   api — только type DTO
ui           →  лист, core и engine.  Не знает stores, api, events, phases, controllers
```

Последняя строка и есть граница ui/controller в машинной форме: **вид не может подписаться на стор,
потому что не может его импортировать**.

- **`ui/`** — то, что рисуется: наследник `Container` (или `Text`) с методами игровой семантики
  (`spin`, `land`, `show`, `setValue`, `fadeTo`). Не знает сторов, эмиттера и DI.
- **`controllers/`** — логика над видом: `@injectable`, наследник `LiveContainer`, подписки через
  `watch`/`listen`, форматирование данных и вызовы методов вида.
- **`scenes/`** — раскладка: собирает контроллеры и расставляет их по экрану.

### Поток данных раунда

**Событие view → фаза автомата → сеть → сторы + эмиттер → контроллер → класс анимации → Spine.**

Автомат координирует поток: он единственный писатель в сторы и единственный источник игровых событий.
Сервер — источник правды: клиент показывает присланный результат и ничего не пересчитывает.

У игры без сервера (toybox) источник правды — сам клиент, и роль ответа играет бросок `Math.random`.
Броски делают фазы: исход раунда принадлежит им. Разбор исхода на состояние сцены (куда упадёт
игрушка, что осыплется) остаётся контроллеру. В граф DI генератор не кладётся — чистые функции
(`resolveDrop`, `getSettleSlides`, `pickFumbleCell`) принимают его параметром и тестируются
сидированным `createRandom`, а сценарные тесты подменяют `Math.random` через `vi.spyOn`.

### Правила взаимодействия

- **Вверх (view → логика) — событие** в прошедшем времени: view сообщает, что произошло.
- **Вниз (автомат → view) — прямой вызов метода контроллера**, возвращающего промис
  (`await reelsMachine.land(...)`): фаза обязана дождаться конца анимации, а `emit` ничего не возвращает.
  Исключение — движение, которое идёт рядом с раундом и его не задерживает (осыпание кучи в toybox):
  метод синхронный, состояние он меняет сразу, а анимацию доигрывает сам под сигналом своей жизни
  и ловит её ошибку в `notifyError`. Плавающий промис такой метод наружу не отдаёт.
- **Намерение игрока внутри раунда** (Stop) фаза принимает подпиской на время фазы — `emitter.on` с
  `signal` её области — и передаёт вниз вызовом метода: `reelsMachine.slam()`. Stop, нажатый до посадки или
  падения, машина запоминает и применяет при их старте. Контроллеры UI-события раунда не слушают.
- **Фаза, принимающая намерение игрока, проверяет его доступность по стору** (`filter` у `waitFor`,
  условие в обработчике Stop); доступность кнопки отображает тот же флаг.
- **Широковещательные события автомата** (`spin:started`, `spin:landed`, `respin:started`,
  `respin:landed`, `holdWin:started`, `holdWin:spinStarted`, `holdWin:landed`, `holdWin:collected`,
  `cascade:started`, `cascade:landed`)
  объявляют момент раунда для
  подсистем без отношения владения (звук, аналитика). Ответа фаза не ждёт, порядок презентации на них
  не завязывается. Момент обязан совпадать с именем: `spin:landed` — после `await reelsMachine.land(...)`.
- **События сцены для подписчиков**: `ui:buttonTapped` (тап любой кнопки, эмитится после её действия),
  `reel:landed` (барабан встал), `reel:anticipationStarted` (барабан начал паузу anticipation; её
  конец — `reel:landed` того же барабана) и `holdWin:cellLanded` (ячейка бонуса встала). Их слушает звук; фазы и контроллеры на них не завязываются.
- **Состояние раунда пишет только автомат**: фазу, ответ сервера, баланс, шаги раунда, турбо-серию
  (`isTurboSeries`). **Ввод игрока пишут контроллеры ввода** экшенами стора: настройки (ставка, режим,
  звук, турбо, заказ механики), открытие настроек, зажатую кнопку спина (`holdSpin` / `releaseSpin`).
  Экшен сам проверяет доступность по стору: настройки меняются только в `idle`, отпускание спина
  принимается в любой фазе.
- **Две системы наблюдения не смешиваются**: эмиттер — дискретные моменты, MobX — непрерывное
  состояние. У события не бывает «текущего значения»; если оно есть — это стор.

### Композиция и DI

Composition root — [app/container.ts](web/src/app/container.ts) (контейнеры) и
[app/bindings.ts](web/src/app/bindings.ts): `bindApp` — транспорт через `bindNet` пакета `net`, адрес
опцией. Рантайм и состав самой игры приносит её манифест — [games/slot/bindings.ts](games/slot/src/bindings.ts):
`bindFsm` (движок автомата), `bindEngine` (хост и тикер), `bindSpinePool` и `bindAudioSynth` — по
надобности игры, дальше её эндпоинты, сторы, фазы и сцена.

- **Композиционный корень не знает игру статически.** `createGameContainer(bindGame)` принимает
  биндер аргументом, и знает игру только её страница. Иначе вторая игра склеится с первой в один чанк.
- **Контракт игрового модуля** — [games/slot/index.ts](games/slot/src/index.ts): `preload`, `bind`,
  `start(container, element, signal)`. Это вход `.` пакета игры; других модулей игры страница не импортирует.
- **Два времени жизни = два контейнера.** App-контейнер живёт всю вкладку (транспорт);
  child-контейнер — один маунт страницы игры (хост, тикер, пул, эмиттер, сторы, сцена, контроллеры,
  фазы, автомат). Оба — `defaultScope: 'Singleton'`. Уровень биндинга выбирается по **времени жизни**
  сущности, а не по месту использования; скоуп стора = скоуп его состояния.
- **Внутри уровня видимость плоская, дерево — про владение.** Любой класс инжектит любой токен своего
  и родительского уровня. Дерево `GameRoot → GameScene → контроллеры → виды` отвечает
  «кто кого создаёт и уничтожает», а не «кто что видит».
- **Сервисы** — `@injectable()` + явный `@inject(<PKG>_TOKENS.X)` на каждом параметре + `.to(Class)`.
  **Конфиг и дженерики** — `toDynamicValue` без декораторов, конфиг живёт в композиции. Общий класс,
  которому нужно знание игры, получает его конфигом: `FsmConfig` (имена фаз), `CanvasConfig`
  (пропорции макета), `SpinePoolConfig` (состав скелетов).
  **Не-сервисы** (виды, value-объекты, PIXI-детали) создаёт класс-владелец, в DI они не биндятся.
- **Асинхронно-рождающиеся ресурсы в граф не кладём**: PIXI `Application` обретает поля только после
  `await init()`, поэтому им владеет `GameRoot`, а не контейнер.
- **`container.get()` — только в `app/`, роут-страницах и `start` игрового модуля.** Слои получают
  зависимости конструктором и импортируют лишь значение токенов.
- **Смерть — через контейнер**: `onDeactivation` пишется рядом с `bind()`, деактивации синхронные,
  идемпотентные (destroy — под guard'ом `destroyed`) и порядконезависимые. Порядкозависимые смерти
  зашиты в `destroyGameContainer`: `Fsm` (остановить автомат) → `SpinePool` (свободные скелеты живут
  вне сцены и обязаны умереть до рендерера) → `GameRoot` (`app.destroy` каскадом уносит сцену) →
  `unbindAll()` хвостом. Попадает сюда только то, что держит PIXI-объекты вне дерева сцены.
- **Как расширять.** Контроллер: класс → токен → `bind` с guard-деактивацией → `@inject` в `GameScene`
  и место в `layout`. Так подключаются узлы сцены и переиспользуемые контроллеры. Контроллер-лист,
  нужный одному владельцу, создаёт владелец через `new` и передаёт ему зависимости конструктором;
  токена и биндинга у листа нет, он уничтожается каскадом `destroy` владельца. Кнопка — обычный контроллер: создаёт `Button` с опцией `onTap` и ведёт его
  доступность подпиской. Вид: класс
  в `ui/`, создаёт его контроллер — композиция не меняется. Фаза: класс → имя в `PhaseName` →
  `bind(CORE_TOKENS.Phase)` → `return`-переходы соседних фаз, движок не трогается.
  Игра: пакет `games/<name>` с контрактом во входе `.` → зависимость и роут-страница в `web` → имя в
  `GAMES` у [eslint.config.js](eslint.config.js) → `turbo.jsonc` пакета с входами e2e по образцу
  [слота](games/slot/turbo.jsonc) → ассеты в `web/public/games/<name>/`.
- **Игра в разработке**: её страница показывает заглушку строкой, канвас открывается флагом `?play` —
  им же e2e проверяет запуск в прод-сборке. Пакет игры импортируется статически, как у готовой игры:
  ленивый чанк страницы приходит из роутера.

## Правила по слоям

**`net/` и `<game>/api/`** — общий транспорт `WsTransport` (`request`/`subscribe`/`disconnect`),
частные классы-фасады `<name>-api.ts` с zod-схемами. Конфиг в класс не зашит: `url` приходит опцией
из композиции. Формат конверта — SignalR-подобный `{ request, response }`, обёртку строит общий
хелпер `envelope`; **наружу фасад отдаёт `result`** — про конверт знает только он. Входящее сообщение
парсится `safeParse`, невалидное игнорируется; серверная ошибка (`response.error`) реджектит запрос
сразу. `request` отменяем: `signal` — тот же, что фаза передаёт в анимации. Свободных обёрток над
методами не выносим — деструктуризация теряет `this`.

**Состояние запроса держит вызывающий, а не отдельная обёртка.** Фасад возвращает голый промис и
кидает исключение — его одинаково удобно `await` в фазе, `yield` в mobx-`flow` и звать из
`useEffect`. В игре запросом владеет фаза: `try/catch`, готовый DTO кладётся в стор экшеном, а
статус загрузки для вью — это `phase`. React достаёт сеть хуком `useApi()` (`ApiProvider` получает
сервисы пропсом из `app/`). Push-подписки ставит владелец через `transport.subscribe` и снимает
своей смертью.

**`stores/`** — только MobX-классы. Разметка **legacy-декораторами** у объявления члена +
обязательный `makeObservable(this)` в конструкторе; `makeAutoObservable` и карты-объекты запрещены.
`@observable.ref` — для DTO, ошибок и чужих инстансов; глубокий `@observable` — для своих примитивов
и структур. Поле-`flow(...)` декоратором не помечается. Мутации в async-коде — в `runInAction`;
включён `enforceActions: 'always'`. **Стор игры пассивен: в сеть он не ходит** — ответы приносят
фазы экшенами (`applyInit`, `applySpin`), а активную фазу пишет туда же движок автомата через
`setPhase` (стор реализует `PhaseSink`, отдельного стора у автомата нет). Если стор всё-таки владеет своим запросом (лобби,
настройки вне раунда), это обычный `flow`/async-экшен, а не общая обёртка. MobX — для игрового
состояния, UI-состояние интерфейса живёт в React. Подписка на стор в `engine/` и `games/` — только
через `watch` базы `LiveContainer` (прямой импорт `reaction`/`autorun`/`when` там запрещён ESLint).

**`core/easing.ts`** — кривые движения: чистая математика без PIXI, поэтому ей пользуются и
PIXI-слой, и React-кит (фон лендинга). Всё, что не зависит ни от PIXI, ни от React и нужно обоим,
живёт в `core/` — это единственное место, откуда виден и тот, и другой. Исключение — рил-машина:
пакет `reels` не зависит от `core`, нужные ему кривые лежат в его собственном `easing.ts`.

**`core/events/`** — `GameEmitter` (обёртка над `eventemitter3`; PIXI тянет его же, поэтому в бандле
он один, а слой событий обходится без PIXI) и карта `GameEvents` на стороне игры.
Все имена событий заводятся только в карте, payload проверяет компилятор. Payload несёт данные
момента; значения с «текущим состоянием» подписчик читает из стора. `on()` возвращает функцию
отписки; в дереве сцены подписываемся через `this.listen`, фаза принимает событие через `waitFor`
(дождаться) или `on` с `signal` своей области (реагировать всю фазу) — подписку снимает событие или
`signal`. `on()` без `signal` зовут только `core/events` и `LiveContainer`. `off(event)` без колбэка и `removeAllListeners()` не вызываем — снимут чужое.
Утечки диагностируются `listenerCounts()`.

**`core/errors/`** — свободные функции над window-событием `app:notice`, типизация через аугментацию
`WindowEventMap`. Шина именно window-событие, а не эмиттер и не DI: слой обязан оставаться листом
графа, иначе `main.tsx` и `Layout` утянут PIXI в стартовый бандл лендинга. Два уровня:
`notifyError` — восстановимая ошибка, снекбар; `notifyFatal` — рантайм игры остановлен, оверлей над
канвасом. Отмена (`AbortError`) — не ошибка, отсеивается на входе. Пустой `catch` не пишем: где
показывать нечего — `traceError`. Перехватчики последнего рубежа — `installGlobalHandlers()` и
колбэки `createRoot`; по пути ошибки ловят `errorElement` роутера, `GameTicker.update`,
`webglcontextlost` и guard подписок `LiveContainer`.

**`core/fsm/` и `<game>/phases/`** — общий движок и частные фазы `booting → idle → spinning →
result → idle`, по файлу на фазу. `spinning` держит всё движение барабанов, от старта до посадки и
`spin:landed`; `result` — только презентацию выигрыша. Пока в ответе спина есть следующий шаг
каскада, `result` коротко показывает выигрыш и возвращает раунд в `cascade`: фаза взрывает
выигравшие символы и сажает падение на кадр шага, затем снова `result`. Пока есть следующий шаг
респина, `result` возвращает раунд в `respin`: фаза без сети крутит неудержанные барабаны и сажает
их на кадр шага, затем снова `result`. После респинов бонус Hold & Win идёт своими фазами:
`holdWinIntro` меняет доску, `holdWinSpin` — по шагу ответа за вход (фаза возвращает себя, пока шаги
есть), `holdWinCollect` собирает монеты и отдаёт раунд в `result`. В турбо-серии `result` возвращает раунд в
`spinning`, пока спин зажат и хватает на ставку.

Цикл toybox — `booting → idle → descending → grabbing → ascending → delivering → releasing →
returning → idle`. `descending` сажает клешню на верх стопки под ней, `grabbing` разыгрывает захват,
`releasing` выдерживает паузу над лотком и отдаёт донесённую игрушку в счётчик. Каждая фаза цикла
держит в хвосте общую паузу, чтобы движения не склеивались встык. **Потеря игрушки — момент внутри
хода, а не отдельная фаза:** на подъёме (`ascending`) и по дороге к лотку (`delivering`) ход идёт
одним движением `claw.ascend` / `claw.carryTo`, и клешня разжимается прямо в нём, отдавая игрушку
через `onDrop`. Переход фазы разорвал бы ход на два движения, и привод затормозил бы до нуля в точке
потери, а игрушка ждала бы конца хода без родителя. Момент считает сама клешня: долю хода — до ячейки
пути или заданную броском фазы — переводит в долю времени `easeTrapezoidInverse`, потому что привод
разгоняется и тормозит.
Перекладка игрушек внутри кучи (падение, отскоки, осыпание) клешню не задерживает: стопки
пересчитываются сразу, а движение доигрывается фоном под сигналом `ContentsController`.

Движок имён игры не знает: стартовая фаза и полный набор приходят
значением `FsmConfig` из композиции, а активную фазу он публикует в `PhaseSink` — им работает стор
игры. Фаза — `@injectable`-класс
`{ name, enter(signal), exit?() }`; `enter` **возвращает имя следующей фазы**, переход изнутри фазы
не делается. Данные раунда грузит стартовая фаза `booting` и объявляет готовность событием
`game:booted` — хост отвечает только за PIXI-мир. Внутри фазы нет цикла: появился `while` — это две фазы.
Зависимости фаза объявляет сама через `@inject`, `signal` приходит аргументом `enter`.
Ошибка фазы фатальна и терминальна: петля выходит навсегда, движок объявляет её `notifyFatal`,
поэтому `start()` не реджектится и зовётся как `void`. Ошибка запроса не фатальна — фаза
откатывает ставку, зовёт `notifyError` и возвращает раунд в `idle`. Сеть и анимация запускаются
параллельно; промис возвращают только методы с концом. Выдержки презентации держит фаза, содержимое
текста выбирает контроллер по стору. Показ вне раунда (превью линий при смене режима) принадлежит
контроллеру, а не автомату.

**`reels/` и `reels-pixi-adapter/`** — рил-машина разнесена на модель и рендер по образцу
headless-таблиц: пакет `reels` содержит данные раунда, состав барабанов и расчёт их движения, адаптер
переносит слоты модели в PIXI-view. Оба пакета — самостоятельные библиотеки: модель не зависит ни от
одного пакета монорепо, адаптер — только от модели, `pixi.js` у него peerDependency. Доступа к тикеру у модели нет: величину шага
приносит адаптер вызовом `advance` из своего тикер-колбэка, одного на всю машину. Считает она в
абстрактных единицах длины: `cellHeight` приходит конфигом, единицу выбирает игра. Два понятия ячейки: `Cell` —
стабильный адрес `(барабан, ряд)` с `getValue`/`getSlot`, по нему контроллеры игры находят значение
раунда и View-компонент ячейки (`ReelsView.getCellView`);
`StripSlot` — движущийся слот ленты, с ним работает рендер. Состав барабанов приносит игра значением
`ReelsConfig`, view ячейки — фабрикой `createCellView`: своего арта у адаптера нет. Новая
механика — это стратегия (`SpinStrategy`, `LandingStrategy`, `FallStrategy`) или правка модели, адаптер не трогается.

**`engine/` и сцена игры** — PIXI-слой. Контроллер — наследник `LiveContainer`: создаёт виды и
держит подписки через `watch`/`listen` (свой `destroy` для отписок не нужен). Вид — наследник
`Container` с методами игровой семантики (`spin`, `land`), поэтому смена реализации
(спрайт ↔ Spine ↔ `Graphics`) не задевает ни контроллер, ни фазы. Не всё рисуется скелетами: часть
собрана из спрайтов и `Graphics` — выбор за видом. В `engine/` лежат только те базы, которые не
зависят от арта: `LiveContainer` и `SpineAnimation`; адаптер барабанов — отдельный пакет. Кнопка и текст со
своим артом и геометрией общими не бывают — они живут в `<game>/ui/`.

**`engine/audio/` и звук игры** — `AudioSynth` собирает звуки из осцилляторов, шума и фильтров
Web Audio API по рецептам-данным; аудиоассетов нет. `AudioContext` создаётся на первом звуке (он
всегда вызван жестом игрока), в скрытой вкладке засыпает вместе с тикером. Рецепты — знание игры, они
живут в листе `<game>/sounds.ts`, общую громкость игра приносит конфигом `AudioConfig`. Играет их
`SoundController`: он подписан на события и стор через `listen`/`watch` и ничего не рисует, а в дереве
сцены стоит ради владения подписками. Фазы о звуке не знают. Флаг `isSoundOn` — настройка вне раунда,
её хранит сам стор в `localStorage` через `core/storage.ts`.

**Мост React ↔ PIXI** — общий компонент `GameCanvas` (место под канвас в React-дереве; сам
PIXI-мир держит `GameRoot` на стороне движка): `useRef` + `useEffect` с очисткой, callback-ref
без cleanup не используем. Игру он получает пропсами `boot`/`dispose` и потому не знает ни одной.
Бутстрап двухфазный: сперва `preload()` ассетов, затем сборка графа — конструкторы читают кэш
синхронно. Оверлей загрузки снимается, когда резолвится `start` игрового модуля (он ждёт
`game:booted`); провал бутстрапа отдаётся исключением и показывается через `notifyFatal`.
Локальный флаг `disposed` защищает от гонки StrictMode вокруг каждого `await`.

**`components/` и `pages/`** — функциональные компоненты, Tailwind в `className`; CSS-модулей и
styled-components нет, глобальный стиль один. Брендовые цвета — токены `@theme`, их TS-двойник для
PIXI — `PALETTE` (живёт в `core/`, чтобы её видели и PIXI-слой, и React-кит). Страницы грузятся
лениво через `lazy` в роутере. Провайдеры приложения — `StrictMode → ApiProvider → RouterProvider`.
Ручную мемоизацию не добавляем — работает React Compiler. CSS сторонних библиотек (Swiper)
подключается в `styles/index.css` через `@import … layer(components)`: CSS без слоя перекрывает
утилиты Tailwind при любой специфичности, и классы на элементах библиотеки не применяются.

## PIXI / канвас

- Инициализация асинхронная (`await app.init(...)`), защита от двойного маунта StrictMode —
  поле `pending` у владельца.
- **Размер канваса зависит от размеров контейнера** и считается `getCanvasSize` по `CanvasConfig`:
  до `fillMaxWidth` (телефон) канвас занимает контейнер целиком, выше — бокс с пропорциями макета во
  всю высоту доступной области. Изменения отслеживает `ResizeObserver` контейнера, каждый пересчёт
  вызывает `renderer.resize` и `layout` сцены; `resizeTo` не используем.
- **Разницу пропорций компенсирует сцена**: фон масштабируется по `max` (полное покрытие канваса,
  обрезка по краям), контент — по `min` с центрированием. Фон и контент лежат в разных контейнерах,
  у самой сцены масштаб не задаётся.
- **Порядок наложения в изометрии — один сортируемый слой и один ключ.** Правило раскладки куба:
  у предмета есть точка мира — он прямой ребёнок слоя содержимого (`ContentsController`,
  `sortableChildren`) и сам держит `zIndex = getDepthOrder(своей точки)`; точки нет (плоскость пола,
  рёбра каркаса) — он лежит под слоем и в сортировке не участвует. Так в один слой попадают игрушки,
  стенки лотка и клешня. Ключ даёт смещение точки против луча взгляда — вектора, который
  проецируется в ноль; экранная высота ключом не годится, потому что у точек на одном луче она
  совпадает. Ключ ставится там же, где позиция, поэтому переехавшая игрушка встаёт в глубину новой
  стопки сама.
- Рендер переводится на **игровой тикер** из контейнера (`app.ticker = ticker`), дальше тикером
  владеет приложение. Функции в тикер добавляются стабильной ссылкой — иначе их не снять.
- **`GameTicker.destroy` не зовёт `super.destroy()`**: `Application.destroy` убивает плагины до
  сцены, а каскад `stage.destroy` дальше зовёт `ticker.remove`.
- **Всё, что PIXI не уничтожает каскадом, обязано умереть до `app.destroy`** — см. порядок разборки.
- **Игровые задержки — только `waitTicks`**, не `setTimeout`: в свёрнутой вкладке тикер стоит, и
  анимация завершилась бы по таймеру, не отрисовав ни кадра. `setTimeout` допустим как watchdog
  по системному времени (`waitFor`, транспорт) и в моках.
- **Скелеты создаёт и уничтожает только `SpinePool`** — классы берут их через `attach` и
  возвращают через `detach`; пересборка скелетов на каждый символ давала мажорные GC. В `release`
  обязателен полный сброс позы, треков и слот-объектов. Статичные позы держатся с `autoUpdate = false`.
  Сейчас пул собирает спрайтовый стаб (`createStubSkeleton`) по описаниям, которые игра приносит
  конфигом `SpinePoolConfig`; возврат на Spine — правка одного метода `SpinePool.create`, остальной
  код скелета не знает и видит только тип `SkeletonLike`.
- Учитывай доступность: декоративная анимация подключается только без `prefers-reduced-motion`.
- **У интерактивных View-компонентов `accessiblePointerEvents = 'none'`.** Слой доступности снимается только
  движением мыши, на тач-устройствах он остаётся, и его DOM-кнопки перехватили бы `pointerdown` у
  канваса. Клавиатура и скринридер активируют кнопки и так. Долгий тап по канвасу на iOS гасят
  `select-none` и `-webkit-touch-callout: none` на `GameCanvas`.
- Фон лендинга грузит PIXI **динамическим `import()`**: компонент стоит в глобальном Layout.

## Ассеты

- Ассеты игры лежат в `web/public/games/<game>/` — по папке на игру. Каталог `public` у Vite один,
  поэтому ассеты игр лежат в приложении
- **Почему `public/`, а не `src/`**: их грузит `Assets.load` по строковому URL в рантайме, ESM-импорта
  нет, в граф сборки Vite они не попадают.
- **Все URL — в одном манифесте** [games/slot/assets.ts](games/slot/src/assets.ts); **единственный
  `Assets.load` в проекте** — `preloadGameAssets`, его зовёт `preload` игрового модуля до сборки графа. Дальше всё читается из
  кэша синхронно (`Assets.get`, скелет из пула); `Assets.load` внутри классов не появляется.
- **Вложенность внутри пака не менять**: `.atlas` ссылается на свою страницу голым именем файла.
- **Регистр в путях сверяй с диском**: APFS регистронезависима, поэтому опечатка проявится только на
  прод-раздаче — PIXI получит SPA-фолбэк вместо ассета и упадёт на декодировании.
  ```bash
  cd web/public/games/slot && find . -type f | sed 's|^\./||' | sort   # сверить с путями из assets.ts
  ```
- **SVG-иконки игры — всегда белые**: tint PIXI умножает цвет, чёрному источнику цвет не задать.

## Конвенции кода

**Раскладка файлов в слое** одинакова везде:

- **`<name>.ts`** — класс и ничего кроме: ни свободных функций, ни типов, ни констант, ни синглтонов.
- **`types.ts`** / **`constants.ts`** / **`utils.ts`** / **`tokens.ts`** — типы, константы, утилиты
  и DI-токены пакета. Общее для нескольких пакетов живёт в `core/`.
- **`utils/` (папка)** — когда утилиты слоя сами классы: по классу на файл.
- Единственное исключение — **zod-схемы api-слоя**: они живут в файле класса, который ими парсит.
- Пустых файлов-заготовок не создаём; module-scope синглтонов нет (исключение — composition root).

**Folder-as-module** — только для компонентов, страниц и контракта игры (папка с `index.ts(x)`,
импорт на папку). Внутри пакетов — плоские файлы, импорт на файл, баррелей нет: именно это делает
один пакет безопасным для бандла — импорт `core/errors/utils` не тянет `engine/`.
Исключение — пакеты-библиотеки `reels` и `reels-pixi-adapter`: их публичный API — баррель
`src/index.ts`, единственный вход в `exports`, пакет помечен `"sideEffects": false`. Внутри пакета
баррель не используется: модули импортируют друг друга напрямую, иначе появятся циклы.

**Именование: роль называет папка, а не имя файла.**

- **Папка-роль** (`ui/`, `controllers/`, `phases/`, `stores/`, `api/`, `scenes/`) — имя файла это
  голая сущность, суффикс роли живёт в имени класса: `controllers/spin-button.ts` →
  `SpinButtonController`, `phases/idle.ts` → `IdlePhase`, `stores/slot.ts` → `SlotStore`,
  `api/slot.ts` → `SlotApi`, `scenes/game.ts` → `GameScene`. В `ui/` суффикса нет — там сущность
  и есть вид, поэтому пары читаются один-в-один: `ui/win-overlay.ts` ↔ `controllers/win-overlay.ts`.
- **Папка-подсистема** (`errors/`, `events/`, `fsm/`, `skeleton/`, `mocks/`) — имя файла это
  kebab-case имени класса: `events/game-emitter.ts` → `GameEmitter`.
- **Зоны внутри папки-роли** — `ui/hud/`, `ui/reels/`, `controllers/hud/`, `controllers/reels/`:
  группировка по части экрана, роль по-прежнему задаёт верхняя папка. Пары ui↔controller лежат на
  одинаковом пути: `ui/reels/win-overlay.ts` ↔ `controllers/reels/win-overlay.ts`.
- **Видовые файлы** — `types.ts`, `constants.ts`, `utils.ts`, `tokens.ts`, `bindings.ts`, `index.ts`.
- **DI-токен называется как класс, который он резолвит.**

Остальное: папки-компоненты `PascalCase`, прочие файлы `kebab-case`; страницы с суффиксом `Page`,
иконки — `Icon`; константы — `SCREAMING_SNAKE_CASE`.

**Экспорты и типы** — только именованные экспорты (default — лишь у SVG через `?react`).
Компоненты — стрелочные `export const` без `React.FC`, пропсы — `interface XxxProps` рядом.
DTO-типы `z.infer` — рядом со своими схемами. `any` запрещён, вместо `@ts-ignore` — `@ts-expect-error`.
Type-only импорты обязательны. Enum-подобные наборы — `as const`-объект + производный тип, не `enum`.

**Импорты** — чужой пакет по имени (`@pixi-demos/core/errors/utils`), свой — через поле `imports`
его `package.json` (`#src/errors/utils`); в `web` для своих файлов — алиас `src/*`. Относительные
пути только для соседних и дочерних файлов. Порядок навязан ESLint (`builtin → external → internal`,
`react` первым, алфавит); пакеты монорепо, `#src/*` и `src/*` — группа internal.

**TypeScript** — строгий, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `noUnusedLocals/Parameters`.
Неиспользуемые параметры — с префиксом `_`. Включены legacy-декораторы под inversify,
`emitDecoratorMetadata` выключен — токены в `@inject` всегда явные. Parameter properties
(`constructor(private x: X)`) запрещены `erasableSyntaxOnly`.

**Асинхронность** — `async/await` + `try/catch`; `.then()/.catch()` не используем (исключение —
конструктор deferred-промиса, который резолвится извне). Плавающий промис запрещён линтером: его
либо ждут, либо помечают `void`, и тогда обработка ошибок обязана быть внутри самой функции.

**Форматирование** — `.prettierrc.json` описывает стиль (без точек с запятой, одинарные кавычки,
120 колонок), но на pre-commit гоняется только `pnpm lint` — автофиксы ESLint и `tsc`. Формат
держится IDE и глазами; вручную переформатировать чужой код не надо.

**Моки** включаются флагом `USE_MOCKS`, объявленным прямо в [main.tsx](web/src/main.tsx): свёртка условия
в литерал внутри того же модуля — единственное, что выбрасывает msw из прод-бандла. После правки
`main.tsx` проверяй: `pnpm build && grep -rl setupWorker web/dist/assets/` должен молчать.

## Комментарии в коде

Проект учебный, но инлайн-доки короткие и сухие: разбор «зачем» идёт в чат, договорённости — сюда.

- **Классы, публичные методы и утилиты** — JSDoc «что делает», 1–2 строки, сухой инженерный язык.
  Запрещены клише, дихотомии («это, а не это»), метафоры и сленг, кроме технического.
- Точечные `//`-пояснения — только у неочевидных решений, одна-две строки.
- Комментируй **только новое и изменённое**; в существующий неизменённый код комментарии не дописывай.
- Сергей при ревью может удалять и править комментарии — не возвращай их.

## Чего избегать

- Не вводи `any` и `@ts-ignore`; не оставляй `console.*` и `debugger` — исключения: `traceEvent`,
  `tracePhase`, `traceError`.
- Не глуши ошибку пустым `catch`, не оставляй плавающий промис.
- Не заводи вторую шину ошибок и не добавляй уведомления в карту `GameEvents`.
- Не используй `setTimeout` для игровых задержек — только `waitTicks`.
- Не зови `super.destroy()` в `GameTicker.destroy` и не создавай скелеты вне `SpinePool`.
- Не заводи module-scope синглтоны и не вызывай `container.get()` вне `app/`, роут-страниц и `start`
  игрового модуля.
- Не вешай async-обработчики на `onDeactivation`; `unbindAll()` — только хвост после
  порядкозависимых `unbind`.
- Не подписывайся в `engine/` и `games/` напрямую (`reaction`, `emitter.on`) — только `watch`/`listen`,
  в фазах — `waitFor` и `on` с `signal` области фазы.
- Не делай тяжёлые PIXI-инстансы observable и не клади в `stores/` не-MobX-классы.
- Не води сеть из стора игры и не заводи обёрток над запросом: промис возвращает фасад, состоянием
  владеет вызывающий.
- Не рисуй в контроллере и не подписывайся на стор в виде: линт-границы `ui/` это ловят.
- Не используй `makeAutoObservable` и карты-объекты `makeObservable(this, {...})`.
- Не добавляй ручную мемоизацию без нужды.
- Не добавляй в файл с классом типы, константы и свободные функции.
- По нерешённым техвыборам решений не принимай — сперва уточни.
