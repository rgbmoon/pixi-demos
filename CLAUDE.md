## Обзор

Пет-проект для изучения PIXI.js и геймдева. Цель — слот-машина.

**Статус** Сквозной спин работает: кнопка → сеть → сторы → контроллеры → скелеты. Барабаны
крутятся и садятся на серверные символы, счёт ведётся по данным сервера, линии выплат рисуются,
ошибки доходят до игрока. Звука нет.

**Стек:** React 19 · PIXI.js v8 · MobX 6 · inversify 8 · Tailwind CSS v4 · react-router-dom v7 ·
TypeScript 6 · Vite 8; сеть — zod + partysocket, моки — MSW, скелеты — стаб из `engine/skeleton`.
Рантайм `@esotericsoftware/spine-pixi-v8` остаётся в зависимостях, но сейчас не импортируется:
Spine-ассеты лицензионные и в репозиторий не попадают. Версия пинована тильдой `~4.2.x` —
major.minor рантайма обязан совпадать с версией редактора, экспортировавшего ассеты (4.2.43).
React Compiler включён для JSX-файлов
(babel не парсит декораторы в `.ts`, см. [vite.config.ts](vite.config.ts)).

## Архитектура

### Слои и направление импортов

Каждая папка верхнего уровня — **будущий npm-пакет**: раскладка сделана так, чтобы вынос в
монорепо был механическим. Пакеты разделены по рантайму: чистый TS, zod, React, PIXI.

```
src/
  main.tsx      вход; сюда же подключён styles/index.css
  app/          composition root: контейнеры, биндинги, роутер, провайдеры
  pages/        роут-страницы; каждая — граница ленивого чанка
  core/         чистый TS: errors/, events/, fsm/ (движок), palette, easing, tokens
  net/          транспорт WS, конверт, msw-хелпер; без PIXI и React
  components/   React-кит: Layout, Button, Snackbars, RouteError, BackgroundCanvas,
                GameCanvas, ApiProvider, icons/
  engine/       PIXI-рантайм: хост, тикер, пул скелетов, skeleton/ и базы сцены —
                LiveContainer и SpineAnimation
  games/slot/   сама игра: api/ stores/ phases/ scenes/ mocks/ + листовые tokens, types,
                constants, events, assets, utils, skeletons; ui/ и controllers/ внутри
                разбиты по зонам сцены: hud/ и reels/
  styles/       глобальный стиль и @theme-токены Tailwind
```

- Граф импортов односторонний, `import/no-cycle` включён.
- **Направление между пакетами** проверяет ESLint (`@typescript-eslint/no-restricted-imports`
  с `allowTypeImports`, блок `files:` на пакет):

  ```
  core        →  ничего;                        запрещены pixi.js и react
  net         →  core;                          запрещены pixi.js и react
  components  →  core, net;                     PIXI только динамическим import()
  engine      →  core, net;                     запрещён react
  games/*     →  core, net, engine;             никогда друг в друга и не в components
  pages/*     →  всё, включая свою игру и app
  app         →  всё, кроме games (игру знает только её страница)
  ```

  Предел правила: оно ловит алиасные пути, относительный `../..` за границу пакета — нет.
  Правя блоки, помни: в flat-config правила одного имени **заменяются целиком, а не складываются**,
  поэтому блок слоя обязан повторить пакетный набор — иначе он его молча снимет.

- **Токены — по пакету**: `CORE_TOKENS`, `NET_TOKENS`, `ENGINE_TOKENS`, `SLOT_TOKENS`. Каждый файл
  токенов — **лист графа**: в рантайме только `Symbol`, все классы — `import type` (иначе появятся
  циклы с композицией). `core/errors/` — тоже лист, его импортирует кто угодно.
- **`engine/skeleton/`** — реализация `SkeletonLike` по умолчанию: пока нет Spine-ассетов, скелеты
  рисует стаб. Описания скелетов приносит игра конфигом `SpinePoolConfig`, не сам движок.
- `phases/` вызывает `api/`, пишет в `stores/`, дёргает контроллеры сцены.
- **`phases/` и сцена обмениваются только `import type`**, экземпляры приходят через DI: в рантайме
  зависимости нет. Вверх сцена сообщает событиями, вниз принимает вызовы методов.

### Уровни внутри игры

Вниз импортировать можно, вверх — только `import type`; проверяется тем же правилом:

```
types/constants/tokens/assets  ←  лист
api          →  лист
stores       →  api, лист
phases       →  stores, api, лист;   controllers — только type
scenes       →  controllers, ui, лист
controllers  →  ui, stores, events, лист;   api — только type DTO
ui           →  лист и engine.  Не знает stores, api, events, phases, controllers
```

Последняя строка и есть граница ui/controller в машинной форме: **вид не может подписаться на стор,
потому что не может его импортировать**.

- **`ui/`** — то, что рисуется: наследник `Container` (или `Text`) с методами игровой семантики
  (`spin`, `land`, `show`, `setValue`, `fadeTo`). Не знает сторов, эмиттера и DI.
- **`controllers/`** — логика над видом: `@injectable`, наследник `LiveContainer`, подписки через
  `watch`/`listen`, форматирование данных и вызовы методов вида.
- **`scenes/`** — раскладка: собирает контроллеры и расставляет их по экрану.

### Поток данных раунда

**Событие view → фаза автомата → сеть → сторы + эмиттер → контроллер → класс анимации → Spine.**

Автомат координирует поток: он единственный писатель в сторы и единственный источник игровых событий.
Сервер — источник правды: клиент показывает присланный результат и ничего не пересчитывает.

### Правила взаимодействия

- **Вверх (view → логика) — событие** в прошедшем времени: view сообщает, что произошло.
- **Вниз (автомат → view) — прямой вызов метода контроллера**, возвращающего промис
  (`await reels.land(...)`): фаза обязана дождаться конца анимации, а `emit` ничего не возвращает.
- **Широковещательные события автомата** (`spin:started`, `spin:landed`) объявляют момент раунда для
  подсистем без отношения владения (звук, аналитика). Ответа фаза не ждёт, порядок презентации на них
  не завязывается. Момент обязан совпадать с именем: `spin:landed` — после `await reels.land(...)`.
- **Писать в сторы может только автомат.** Исключение — настройки игрока (ставка, режим, звук):
  их пишут кнопки, а экшены стора пропускают запись только в фазе `idle`.
- **Две системы наблюдения не смешиваются**: эмиттер — дискретные моменты, MobX — непрерывное
  состояние. У события не бывает «текущего значения»; если оно есть — это стор.

### Композиция и DI

Composition root — [app/container.ts](src/app/container.ts) (контейнеры) и
[app/bindings.ts](src/app/bindings.ts): `bindApp` (транспорт) и `bindRuntime` (хост, тикер, пул,
движок автомата). Состав самой игры приносит её манифест —
[games/slot/bindings.ts](src/games/slot/bindings.ts).

- **Композиционный корень не знает игру статически.** `createGameContainer(bindGame)` принимает
  биндер аргументом, и знает игру только её страница. Иначе вторая игра склеится с первой в один чанк.
- **Контракт игрового модуля** — [games/slot/index.ts](src/games/slot/index.ts): `preload`, `bind`,
  `start(container, element, signal)`. Больше страница об игре не знает ничего.
- **Два времени жизни = два контейнера.** App-контейнер живёт всю вкладку (транспорт);
  child-контейнер — один маунт страницы игры (хост, тикер, пул, эмиттер, сторы, сцена, контроллеры,
  фазы, автомат). Оба — `defaultScope: 'Singleton'`. Уровень биндинга выбирается по **времени жизни**
  сущности, а не по месту использования; скоуп стора = скоуп его состояния.
- **Внутри уровня видимость плоская, дерево — про владение.** Любой класс инжектит любой токен своего
  и родительского уровня. Дерево `GameRoot → GameScene → контроллеры → виды` отвечает
  «кто кого создаёт и уничтожает», а не «кто что видит».
- **Сервисы** — `@injectable()` + явный `@inject(<PKG>_TOKENS.X)` на каждом параметре + `.to(Class)`.
  **Конфиг и дженерики** — `toDynamicValue` без декораторов, конфиг живёт в композиции. Общий класс,
  которому нужно знание игры, получает его конфигом: `FsmConfig` (имена фаз), `CanvasConfig`
  (пропорции макета), `SpinePoolConfig` (состав скелетов).
  **Не-сервисы** (виды, value-объекты, PIXI-детали) создаёт класс-владелец, в DI они не биндятся.
- **Асинхронно-рождающиеся ресурсы в граф не кладём**: PIXI `Application` обретает поля только после
  `await init()`, поэтому им владеет `GameRoot`, а не контейнер.
- **`container.get()` — только в `app/`, роут-страницах и `start` игрового модуля.** Слои получают
  зависимости конструктором и импортируют лишь значение токенов.
- **Смерть — через контейнер**: `onDeactivation` пишется рядом с `bind()`, деактивации синхронные,
  идемпотентные (destroy — под guard'ом `destroyed`) и порядконезависимые. Порядкозависимые смерти
  зашиты в `destroyGameContainer`: `Fsm` (остановить автомат) → `SpinePool` (свободные скелеты живут
  вне сцены и обязаны умереть до рендерера) → `GameRoot` (`app.destroy` каскадом уносит сцену) →
  `unbindAll()` хвостом. Попадает сюда только то, что держит PIXI-объекты вне дерева сцены.
- **Как расширять.** Контроллер: класс → токен → `bind` с guard-деактивацией → `@inject` в `GameScene`
  и место в `layout`. Кнопка — обычный контроллер: создаёт `Button` с опцией `onTap` и ведёт его
  доступность подпиской. Вид: класс
  в `ui/`, создаёт его контроллер — композиция не меняется. Фаза: класс → имя в `PhaseName` →
  `bind(CORE_TOKENS.Phase)` → `return`-переходы соседних фаз, движок не трогается.

## Правила по слоям

**`net/` и `<game>/api/`** — общий транспорт `WsTransport` (`request`/`subscribe`/`disconnect`),
частные классы-фасады `<name>-api.ts` с zod-схемами. Конфиг в класс не зашит: `url` приходит опцией
из композиции. Формат конверта — SignalR-подобный `{ request, response }`, обёртку строит общий
хелпер `envelope`; **наружу фасад отдаёт `result`** — про конверт знает только он. Входящее сообщение
парсится `safeParse`, невалидное игнорируется; серверная ошибка (`response.error`) реджектит запрос
сразу. `request` отменяем: `signal` — тот же, что фаза передаёт в анимации. Свободных обёрток над
методами не выносим — деструктуризация теряет `this`.

**Состояние запроса держит вызывающий, а не отдельная обёртка.** Фасад возвращает голый промис и
кидает исключение — его одинаково удобно `await` в фазе, `yield` в mobx-`flow` и звать из
`useEffect`. В игре запросом владеет фаза: `try/catch`, готовый DTO кладётся в стор экшеном, а
статус загрузки для вью — это `phase`. React достаёт сеть хуком `useApi()` (`ApiProvider` получает
сервисы пропсом из `app/`). Push-подписки ставит владелец через `transport.subscribe` и снимает
своей смертью.

**`stores/`** — только MobX-классы. Разметка **legacy-декораторами** у объявления члена +
обязательный `makeObservable(this)` в конструкторе; `makeAutoObservable` и карты-объекты запрещены.
`@observable.ref` — для DTO, ошибок и чужих инстансов; глубокий `@observable` — для своих примитивов
и структур. Поле-`flow(...)` декоратором не помечается. Мутации в async-коде — в `runInAction`;
включён `enforceActions: 'always'`. **Стор игры пассивен: в сеть он не ходит** — ответы приносят
фазы экшенами (`applyInit`, `applySpin`), а активную фазу пишет туда же движок автомата через
`setPhase` (стор реализует `PhaseSink`, отдельного стора у автомата нет). Если стор всё-таки владеет своим запросом (лобби,
настройки вне раунда), это обычный `flow`/async-экшен, а не общая обёртка. MobX — для игрового
состояния, UI-состояние интерфейса живёт в React. Подписка на стор в `engine/` и `games/` — только
через `watch` базы `LiveContainer` (прямой импорт `reaction`/`autorun`/`when` там запрещён ESLint).

**`core/easing.ts`** — кривые движения: чистая математика без PIXI, поэтому ей пользуются и
PIXI-слой, и React-кит (фон лендинга). Всё, что не зависит ни от PIXI, ни от React и нужно обоим,
живёт в `core/` — это единственное место, откуда виден и тот, и другой.

**`core/events/`** — `GameEmitter` (обёртка над `eventemitter3`; PIXI тянет его же, поэтому в бандле
он один, а слой событий обходится без PIXI) и карта `GameEvents` на стороне игры.
Все имена событий заводятся только в карте, payload проверяет компилятор. Payload несёт данные
момента; значения с «текущим состоянием» подписчик читает из стора. `on()` возвращает функцию
отписки; в дереве сцены подписываемся через `this.listen`, вне его — сохраняем отписку и зовём при
смерти владельца. `off(event)` без колбэка и `removeAllListeners()` не вызываем — снимут чужое.
Утечки диагностируются `listenerCounts()`.

**`core/errors/`** — свободные функции над window-событием `app:notice`, типизация через аугментацию
`WindowEventMap`. Шина именно window-событие, а не эмиттер и не DI: слой обязан оставаться листом
графа, иначе `main.tsx` и `Layout` утянут PIXI в стартовый бандл лендинга. Два уровня:
`notifyError` — восстановимая ошибка, снекбар; `notifyFatal` — рантайм игры остановлен, оверлей над
канвасом. Отмена (`AbortError`) — не ошибка, отсеивается на входе. Пустой `catch` не пишем: где
показывать нечего — `traceError`. Перехватчики последнего рубежа — `installGlobalHandlers()` и
колбэки `createRoot`; по пути ошибки ловят `errorElement` роутера, `GameTicker.update`,
`webglcontextlost` и guard подписок `LiveContainer`.

**`core/fsm/` и `<game>/phases/`** — общий движок и частные фазы `booting → idle → spinning →
result → idle`, по файлу на фазу. Движок имён игры не знает: стартовая фаза и полный набор приходят
значением `FsmConfig` из композиции, а активную фазу он публикует в `PhaseSink` — им работает стор
игры. Фаза — `@injectable`-класс
`{ name, enter(signal), exit?() }`; `enter` **возвращает имя следующей фазы**, переход изнутри фазы
не делается. Данные раунда грузит стартовая фаза `booting` и объявляет готовность событием
`game:booted` — хост отвечает только за PIXI-мир. Внутри фазы нет цикла: появился `while` — это две фазы.
Зависимости фаза объявляет сама через `@inject`, `signal` приходит аргументом `enter`.
Ошибка фазы фатальна и терминальна: петля выходит навсегда, движок объявляет её `notifyFatal`,
поэтому `start()` не реджектится и зовётся как `void`. Ошибка запроса не фатальна — фаза
откатывает ставку, зовёт `notifyError` и возвращает раунд в `idle`. Сеть и анимация запускаются
параллельно; промис возвращают только методы с концом. Выдержки презентации держит фаза, содержимое
текста выбирает контроллер по стору. Показ вне раунда (превью линий при смене режима) принадлежит
контроллеру, а не автомату.

**`engine/` и сцена игры** — PIXI-слой. Контроллер — наследник `LiveContainer`: создаёт виды и
держит подписки через `watch`/`listen` (свой `destroy` для отписок не нужен). Вид — наследник
`Container` с методами игровой семантики (`spin`, `land`), поэтому смена реализации
(спрайт ↔ Spine ↔ `Graphics`) не задевает ни контроллер, ни фазы. Не всё рисуется скелетами: часть
собрана из спрайтов и `Graphics` — выбор за видом. В `engine/` лежат только те базы, которые не
зависят от арта: `LiveContainer` и `SpineAnimation`. Кнопка и текст со своим артом и геометрией
общими не бывают — они живут в `<game>/ui/`.

**Мост React ↔ PIXI** — общий компонент `GameCanvas` (место под канвас в React-дереве; сам
PIXI-мир держит `GameRoot` на стороне движка): `useRef` + `useEffect` с очисткой, callback-ref
без cleanup не используем. Игру он получает пропсами `boot`/`dispose` и потому не знает ни одной.
Бутстрап двухфазный: сперва `preload()` ассетов, затем сборка графа — конструкторы читают кэш
синхронно. Оверлей загрузки снимается, когда резолвится `start` игрового модуля (он ждёт
`game:booted`); провал бутстрапа отдаётся исключением и показывается через `notifyFatal`.
Локальный флаг `disposed` защищает от гонки StrictMode вокруг каждого `await`.

**`components/` и `pages/`** — функциональные компоненты, Tailwind в `className`; CSS-модулей и
styled-components нет, глобальный стиль один. Брендовые цвета — токены `@theme`, их TS-двойник для
PIXI — `PALETTE` (живёт в `core/`, чтобы её видели и PIXI-слой, и React-кит). Страницы грузятся
лениво через `lazy` в роутере. Провайдеры приложения — `StrictMode → ApiProvider → RouterProvider`.
Ручную мемоизацию не добавляем — работает React Compiler.

## PIXI / канвас

- Инициализация асинхронная (`await app.init(...)`), защита от двойного маунта StrictMode —
  поле `pending` у владельца.
- **Размер канваса фиксирован**: считается один раз на маунте, `resizeTo` и слушателя `resize` нет,
  `layout` сцены вызывается следом один раз.
- Рендер переводится на **игровой тикер** из контейнера (`app.ticker = ticker`), дальше тикером
  владеет приложение. Функции в тикер добавляются стабильной ссылкой — иначе их не снять.
- **`GameTicker.destroy` не зовёт `super.destroy()`**: `Application.destroy` убивает плагины до
  сцены, а каскад `stage.destroy` дальше зовёт `ticker.remove`.
- **Всё, что PIXI не уничтожает каскадом, обязано умереть до `app.destroy`** — см. порядок разборки.
- **Игровые задержки — только `waitTicks`**, не `setTimeout`: в свёрнутой вкладке тикер стоит, и
  анимация завершилась бы по таймеру, не отрисовав ни кадра. `setTimeout` допустим как watchdog
  по системному времени (`waitFor`, транспорт) и в моках.
- **Скелеты создаёт и уничтожает только `SpinePool`** — классы берут их через `attach` и
  возвращают через `detach`; пересборка скелетов на каждый символ давала мажорные GC. В `release`
  обязателен полный сброс позы, треков и слот-объектов. Статичные позы держатся с `autoUpdate = false`.
  Сейчас пул собирает спрайтовый стаб (`createStubSkeleton`) по описаниям, которые игра приносит
  конфигом `SpinePoolConfig`; возврат на Spine — правка одного метода `SpinePool.create`, остальной
  код скелета не знает и видит только тип `SkeletonLike`.
- Учитывай доступность: декоративная анимация подключается только без `prefers-reduced-motion`.
- Фон лендинга грузит PIXI **динамическим `import()`**: компонент стоит в глобальном Layout.

## Ассеты

- Ассеты игры лежат в `public/games/<game>/` — по папке на игру
- **Почему `public/`, а не `src/`**: их грузит `Assets.load` по строковому URL в рантайме, ESM-импорта
  нет, в граф сборки Vite они не попадают.
- **Все URL — в одном манифесте** [games/slot/assets.ts](src/games/slot/assets.ts); **единственный
  `Assets.load` в проекте** — `preloadGameAssets`, его зовёт `preload` игрового модуля до сборки графа. Дальше всё читается из
  кэша синхронно (`Assets.get`, скелет из пула); `Assets.load` внутри классов не появляется.
- **Вложенность внутри пака не менять**: `.atlas` ссылается на свою страницу голым именем файла.
- **Регистр в путях сверяй с диском**: APFS регистронезависима, поэтому опечатка проявится только на
  прод-раздаче — PIXI получит SPA-фолбэк вместо ассета и упадёт на декодировании.
  ```bash
  cd public/games/slot && find . -type f | sed 's|^\./||' | sort   # сверить с путями из assets.ts
  ```
- **SVG-иконки игры — всегда белые**: tint PIXI умножает цвет, чёрному источнику цвет не задать.

## Конвенции кода

**Раскладка файлов в слое** одинакова везде:

- **`<name>.ts`** — класс и ничего кроме: ни свободных функций, ни типов, ни констант, ни синглтонов.
- **`types.ts`** / **`constants.ts`** / **`utils.ts`** / **`tokens.ts`** — типы, константы, утилиты
  и DI-токены пакета. Общее для нескольких пакетов живёт в `core/`.
- **`utils/` (папка)** — когда утилиты слоя сами классы: по классу на файл.
- Единственное исключение — **zod-схемы api-слоя**: они живут в файле класса, который ими парсит.
- Пустых файлов-заготовок не создаём; module-scope синглтонов нет (исключение — composition root).

**Folder-as-module** — только для компонентов, страниц и контракта игры (папка с `index.ts(x)`,
импорт на папку). Внутри пакетов — плоские файлы, импорт на файл, баррелей нет: именно это делает
один пакет безопасным для бандла — импорт `core/errors/utils` не тянет `engine/`.

**Именование: роль называет папка, а не имя файла.**

- **Папка-роль** (`ui/`, `controllers/`, `phases/`, `stores/`, `api/`, `scenes/`) — имя файла это
  голая сущность, суффикс роли живёт в имени класса: `controllers/spin-button.ts` →
  `SpinButtonController`, `phases/idle.ts` → `IdlePhase`, `stores/slot.ts` → `SlotStore`,
  `api/slot.ts` → `SlotApi`, `scenes/game.ts` → `GameScene`. В `ui/` суффикса нет — там сущность
  и есть вид, поэтому пары читаются один-в-один: `ui/win-overlay.ts` ↔ `controllers/win-overlay.ts`.
- **Папка-подсистема** (`errors/`, `events/`, `fsm/`, `skeleton/`, `mocks/`) — имя файла это
  kebab-case имени класса: `events/game-emitter.ts` → `GameEmitter`.
- **Зоны внутри папки-роли** — `ui/hud/`, `ui/reels/`, `controllers/hud/`, `controllers/reels/`:
  группировка по части экрана, роль по-прежнему задаёт верхняя папка. Пары ui↔controller лежат на
  одинаковом пути: `ui/reels/win-overlay.ts` ↔ `controllers/reels/win-overlay.ts`.
- **Видовые файлы** — `types.ts`, `constants.ts`, `utils.ts`, `tokens.ts`, `bindings.ts`, `index.ts`.
- **DI-токен называется как класс, который он резолвит.**

Остальное: папки-компоненты `PascalCase`, прочие файлы `kebab-case`; страницы с суффиксом `Page`,
иконки — `Icon`; константы — `SCREAMING_SNAKE_CASE`.

**Экспорты и типы** — только именованные экспорты (default — лишь у SVG через `?react`).
Компоненты — стрелочные `export const` без `React.FC`, пропсы — `interface XxxProps` рядом.
DTO-типы `z.infer` — рядом со своими схемами. `any` запрещён, вместо `@ts-ignore` — `@ts-expect-error`.
Type-only импорты обязательны. Enum-подобные наборы — `as const`-объект + производный тип, не `enum`.

**Импорты** — алиас `src/*`, относительные пути только для соседних и дочерних файлов;
порядок навязан ESLint (`builtin → external → internal`, `react` первым, алфавит).

**TypeScript** — строгий, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `noUnusedLocals/Parameters`.
Неиспользуемые параметры — с префиксом `_`. Включены legacy-декораторы под inversify,
`emitDecoratorMetadata` выключен — токены в `@inject` всегда явные. Parameter properties
(`constructor(private x: X)`) запрещены `erasableSyntaxOnly`.

**Асинхронность** — `async/await` + `try/catch`; `.then()/.catch()` не используем (исключение —
конструктор deferred-промиса, который резолвится извне). Плавающий промис запрещён линтером: его
либо ждут, либо помечают `void`, и тогда обработка ошибок обязана быть внутри самой функции.

**Форматирование** — `.prettierrc.json` описывает стиль (без точек с запятой, одинарные кавычки,
120 колонок), но на pre-commit гоняется только `npm run lint` — автофиксы ESLint и `tsc`. Формат
держится IDE и глазами; вручную переформатировать чужой код не надо.

**Моки** включаются флагом `USE_MOCKS`, объявленным прямо в [main.tsx](src/main.tsx): свёртка условия
в литерал внутри того же модуля — единственное, что выбрасывает msw из прод-бандла. После правки
`main.tsx` проверяй: `npm run build && grep -rl setupWorker dist/assets/` должен молчать.

## Комментарии в коде

Проект учебный, но инлайн-доки короткие и сухие: разбор «зачем» идёт в чат, договорённости — сюда.

- **Классы, публичные методы и утилиты** — JSDoc «что делает», 1–2 строки, сухой инженерный язык.
  Запрещены клише, дихотомии («это, а не это»), метафоры и сленг, кроме технического.
- Точечные `//`-пояснения — только у неочевидных решений, одна-две строки.
- Комментируй **только новое и изменённое**; в существующий неизменённый код комментарии не дописывай.
- Сергей при ревью может удалять и править комментарии — не возвращай их.

## Чего избегать

- Не вводи `any` и `@ts-ignore`; не оставляй `console.*` и `debugger` — исключения: `traceEvent`,
  `tracePhase`, `traceError`.
- Не глуши ошибку пустым `catch`, не оставляй плавающий промис.
- Не заводи вторую шину ошибок и не добавляй уведомления в карту `GameEvents`.
- Не используй `setTimeout` для игровых задержек — только `waitTicks`.
- Не зови `super.destroy()` в `GameTicker.destroy` и не создавай скелеты вне `SpinePool`.
- Не заводи module-scope синглтоны и не вызывай `container.get()` вне `app/`, роут-страниц и `start`
  игрового модуля.
- Не вешай async-обработчики на `onDeactivation`; `unbindAll()` — только хвост после
  порядкозависимых `unbind`.
- Не подписывайся в `engine/` и `games/` напрямую (`reaction`, `emitter.on`) — только `watch`/`listen`.
- Не делай тяжёлые PIXI-инстансы observable и не клади в `stores/` не-MobX-классы.
- Не води сеть из стора игры и не заводи обёрток над запросом: промис возвращает фасад, состоянием
  владеет вызывающий.
- Не рисуй в контроллере и не подписывайся на стор в виде: линт-границы `ui/` это ловят.
- Не используй `makeAutoObservable` и карты-объекты `makeObservable(this, {...})`.
- Не добавляй ручную мемоизацию без нужды.
- Не добавляй в файл с классом типы, константы и свободные функции.
- По нерешённым техвыборам решений не принимай — сперва уточни.
